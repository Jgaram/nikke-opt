# 실험 32 — 컨트롤을 원시 입력으로, 큰 컨트롤은 조합 탐색 안에서

> 사람이 등록한 컨트롤 규칙(계산기 기본 레이어 · 패턴 카탈로그 · 정책 이름) 없이 원시 입력과 캐릭터와 무관한 전투 사건만으로
> 컨트롤을 표현하고, 그중 덱 순위를 바꾸는 큰 축은 조합 탐색 안에서 같이 찾으면, 지금 절차(기본 레이어 → 후처리)가 놓친 덱을 찾는가?
> 무엇이 큰 축인지는 정해 두지 않고 잰다.

**상태: R0 · R1 · R2 · R3 완료(2026-11-02). 큰 축 = 버스트 버튼(R2). R3 = 지금 절차(A)가 앞섬 → 「B를 기본으로」 보류, 수정 후 재검증 여부 사용자 확인 대기.** R1은 v2 35/39(기준에 한 덱 모자람), R0는 정정 1건. 사용자 지시(2026-11-02): R2까지 진행 → R3 「시드 둘, 큐브 빼고 추천대로 진행」. 회차 구성 · 판단 기준은 [사용자 확인](#사용자-확인-2026-11-02)을 받았다. 회차마다 실행 전에 사전 등록한다.
진행 방식은 [연구 회차](../../docs/SEARCH.md#연구-회차-계획--실험--해석--다음-방향-결정)를 따른다.

## 사용자 확인 (2026-11-02)

- **회차:** R0 · R1 · R2는 아래 「회차 (안)」대로 확정한다. R3 · R4는 R2 결과(무엇이 큰 축인가)를 본 뒤 설계 · 예산을 다시 확인받는다.
- **판단 기준:** R1 · R3 기준은 초안대로. R2의 x · y는 사용자 선호 없음 → R2 사전 등록 때(결과 전) 같은 덱 축 변형의 흔들림을 근거로 정하고 임시 기준으로 표시한다.
- **R0 범위:** 레이어 켬(지금 절차)에 더해 레이어 끔(계산기 자동만)도 같은 덱으로 잰다 — R1 전에 레이어 의존 크기를 미리 본다.
- **진행(R0 뒤):** 「R2까지 진행」 — R1 · R2를 사전 등록 → 실행 → 결과까지 이어서 한다.
- **R3(R2 뒤):** 「시드 둘 큐브 빼고 추천대로 진행」 — 판 구성 · 탐침 설계(k = 4 · 문턱 0.75 · R2 6시즌으로 고르기)는 계획(안)대로, 예산은 시드 둘(약 22만), 큐브는 두 판 모두 기본 고정.

**해석:** 버스트 버튼은 R2에서 큰 축이었지만, 덱 평가마다 선택지를 더 재는 비용(덱당 5시뮬)이 같은 예산의 탐색 폭을 1/4로 줄여 이득보다 손해가 컸다. 사람 규칙이 없는 니케도 대부분 찾았으나, 전담 규칙형(미란다 · 토브)은 놓쳤다.

**다음(사용자 확인 필요):** 수정 후 재검증의 근거는 있다(비용이 주 원인). 후보: ① 탐색은 P0 바탕 1시뮬로 넓게 하고, 탐침은 끝에 상위 구성(예: 200개 × 4)에만 — 탐색 폭은 A와 같고 탐침 비용은 약 7%. ② 탐침 대신 지금 절차(A)를 유지하고, 규칙 없는 신캐만 원시 메뉴 후처리로 보완. 판단 전에는 R4로 넘어가지 않는다.

## R3 계획 (2026-11-02, 사용자 확인 받음)

**질문:** 큰 축(버스트 버튼)을 덱 평가 안에서 같이 찾으면, 같은 총 시뮬에서 지금 절차(레이어 켬 → 후처리)보다 나은 덱을 찾는가.
사람 규칙이 없어도(레이어 대상 14명을 「규칙 없는 신캐」로 본다) 그 니케가 든 덱을 찾는가.

### 제약 — R2에서 확인한 것

- **모든 덱이 같은 단계 후보 둘 이상을 갖는다**(R2 표본 300: 3단계 둘 273 · 2단계 둘 151 · 1단계 둘 24). 초안의 「S42 기록의 41%에만」은 1 · 2단계만 센 것이다.
- 덱당 버스트 선택지(burst_who + burst_t)는 **중앙 43개**(29~47) — 덱마다 다 재면 사전 계산 덱 수가 1/40로 준다.
- 버스트 이득은 드물다: 1% 이상 40% · 5% 이상 18% 덱.
→ **덱마다 소수(k개)만, 그리고 될 만한 덱에만** 잰다.

### 판

| 판 | 덱 평가(사전 계산) | 후처리(최선 5덱) |
|---|---|---|
| **A** 지금 절차 | 바탕 = 레이어 켬(사람 규칙 포함). 덱 하나 = 1시뮬 | 지금 메뉴(실험 6, 레이어 위) M3:k2 400 × 5덱 |
| **B** 버스트 탐침 | 바탕 = P0(레이어 켬 + 컨트롤 축 전부 끔 — 사람 규칙 없음). 덱 하나 = 바탕 1시뮬 + **문턱을 넘으면 버스트 탐침 k = 4** | 원시 메뉴 v3(아래)의 **작은 축만**(click · cover · camera), 버스트는 탐침 최선으로 고정. M3:k2 400 × 5덱 |

- **탐침 선택지(k = 4):** R2 기록에서 「그 덱 버스트 선택지 중 최선이고 이득 ≥ 1%」였던 횟수가 많은 선택지 종류 상위 4개(종류 = 니케 이름을 뺀 `burst_who<단계>:first=2`, `burst_t:wait2@<단계>/<i번째>` 등). **R2의 시험 4시즌을 뺀 6시즌(S33 · S34 · S35 · S37 · S38 · S40)으로만 고른다**(시험 시즌 정보 누출 방지).
- **문턱:** 바탕 값 ≥ (지금 최선 5덱 중 가장 약한 덱) × 0.75일 때만 탐침한다 — R2 버스트 이득 최대 +36%라 그 아래는 탐침해도 5덱에 들 수 없다.

**미란다 덱 확인(2026-11-02, 시뮬 수십):** 낮은 덱 상위 10개 중 미란다 덱 6개의 버스트 기록을 봤다. 1버는 미란다가 거의 모든 사이클을 썼다(레이어 「전담」이 붙고, 레이어를 꺼도 맨 앞이라 같다). 예외는 미란다 쿨 전에 게이지가 찬 사이클(솔린 : 프로스트 티켓 3번 · 리틀 머메이드 2번). 버스트 순서는 원인이 아니다.
사용자 판단: 미란다는 「공격력이 가장 높은 아군」에게 버프를 줘서 육성에 따라 되는 조합 · 안 되는 조합이 갈린다. 실전 랭커는 버프가 의도대로 들어가게 육성하므로 동등 육성(기본 스펙)과 결과가 다를 수 있다 — **계정별 조사 때 확인할 문제이고 실험 32에서는 다루지 않는다.** (참고: 응답의 `spec.char_defaults.applied`는 요청에 `profile`이 있으면 비어 나오지만 레이어는 붙는다 — 프로필을 빼도 값이 같다.)

**다음:** R1 사전 등록 — 원시 메뉴 구현(버스트 사이클 · 클릭 · 엄폐 앵커), 덱 약 40개에 위 낮은 덱 5개를 더한다.

## 원칙

1. **탐색 변수는 원시 입력과 일반 사건뿐이다.** 원시 입력은 계산기 L0 여섯 개(nikke-calc `docs/CONTROL.md` §L0 — `click` · `cover` · `cover_all` · `focus` · `burst` · `aim`)다.
   「언제」는 캐릭터와 무관한 전투 사건으로 적는다(풀버스트 시작 · 끝, 단계 열림, 쿨 복귀, 재장전 · 남은 장탄, 자기가 건 버프의 시작 · 끝).
   니케 이름이 붙은 규칙 · 카탈로그(`char_defaults.json` `_rules` · `_burst_patterns`)와 정책 이름(장전컨 A~D 등)으로 탐색 공간을 정의하지 않는다.
   출발점은 레이어를 끈 계산기 자동(`operation.auto: true`)이다.
2. **축의 크기는 정하지 않고 잰다.** 어느 축을 조합 탐색 안에서 볼지(큰 축), 후처리로 둘지(작은 축)는 측정 규칙이 정한다.
   신캐 갱신 때 같은 측정을 다시 돌린다 — 갱신 절차의 일부다.
3. **계산기 기본 레이어는 비교 기준이다.** 레이어를 켠 판(지금 절차)과 나란히 재되 탐색에 쓰지 않는다.
4. **실전 덱별 딜은 평가에만 쓴다.** 탐색 · 문턱 조정에 섞지 않는다. 랭커 육성 · 보스 패턴 · 코어가 다르므로 시즌 안 순위 상관으로만 본다.

## 표현 — 원시 입력 + 일반 사건 (회차 1에서 확정)

계산기 요청 v2가 이미 받는 칸으로 적는다(계산기 수정 불필요 — 예외는 아래 「확인할 것」).

| 원시 입력 | 요청 칸 | 일반 사건 어휘 · 파라미터 |
|---|---|---|
| `burst` 버튼 | 배치 순서, `chars.<니케>.control.burst.pattern`(사이클 목록), `.delay`, `.wait_own_cooldown`, `operation.no_burst` | 단계별로 사이클마다 누가 누르나. 일반 정책 족: 선두 고정 · 앞에서부터 쿨 된 니케 · k사이클 교대 · 특정 사이클 전담 · 쓰지 않음 — 니케 이름 없이 「단계 후보 중 i번째」로 적는다 |
| `click` 누르기 · 떼기 | `control.click`(mode tap · hold · auto + window · anchor) | 풀버스트 창(자기 · 전체), 버스트 충전 구간, 앵커 + offset |
| `cover` 시작 · 끝 | `control.reload` · `control.cover`의 앵커 표기(`fb_end` · `next_fb_start` · `own_buff_end` + offset · minus) | 정책 이름 대신 앵커 표기만 쓴다 |
| `cover_all` | `control.sequence` | 사건 기준 구간 |
| `focus`(카메라) | `operation.camera` | 니케 하나 |
| `aim` | — | 허수아비라 제외(2차 목표에서) |

- **확인할 것:** 「이 사이클은 반드시 이 니케」를 강제하는 `burst_sequence`가 요청 v2에 없다. 니케별 사이클 목록은 차례가 아닌 니케도
  앞사람이 다 쿨이면 나가게 둔다. 대부분은 사이클 목록 + 배치 순서 + `no_burst`로 표현되지만, 회차 1 표현력 시험에서 모자라면
  계산기에 요청 칸을 더하는 것을 별도 과제로 올린다.
- 시각 단위 원시 시퀀스 전체(180초 × 5명 × 프레임)는 탐색하지 않는다. 사건에 묶은 파라미터로 줄이고, 그걸로 안 되는 경우만 `sequence`로 찍는다.
