# 실험 32 — 컨트롤을 원시 입력으로, 큰 컨트롤은 조합 탐색 안에서

> 사람이 등록한 컨트롤 규칙(계산기 기본 레이어 · 패턴 카탈로그 · 정책 이름) 없이 원시 입력과 캐릭터와 무관한 전투 사건만으로
> 컨트롤을 표현하고, 그중 덱 순위를 바꾸는 큰 축은 조합 탐색 안에서 같이 찾으면, 지금 절차(기본 레이어 → 후처리)가 놓친 덱을 찾는가?
> 무엇이 큰 축인지는 정해 두지 않고 잰다.

**상태: R1 완료(v2 35/39 — 기준에 한 덱 모자람, 남은 차이는 탐색 1 · 버충 묶음 2 · 불규칙 패턴 1). R2 사전 등록(실행 전). R0 완료(관찰, 정정 1건).** 사용자 지시(2026-11-02): R2까지 진행. 회차 구성 · 판단 기준은 [사용자 확인](#사용자-확인-2026-11-02)을 받았다. 회차마다 실행 전에 사전 등록한다.
진행 방식은 [연구 회차](../../docs/SEARCH.md#연구-회차-계획--실험--해석--다음-방향-결정)를 따른다.

## 사용자 확인 (2026-11-02)

- **회차:** R0 · R1 · R2는 아래 「회차 (안)」대로 확정한다. R3 · R4는 R2 결과(무엇이 큰 축인가)를 본 뒤 설계 · 예산을 다시 확인받는다.
- **판단 기준:** R1 · R3 기준은 초안대로. R2의 x · y는 사용자 선호 없음 → R2 사전 등록 때(결과 전) 같은 덱 축 변형의 흔들림을 근거로 정하고 임시 기준으로 표시한다.
- **R0 범위:** 레이어 켬(지금 절차)에 더해 레이어 끔(계산기 자동만)도 같은 덱으로 잰다 — R1 전에 레이어 의존 크기를 미리 본다.
- **진행(R0 뒤):** 「R2까지 진행」 — R1 · R2를 사전 등록 → 실행 → 결과까지 이어서 한다.

## R2 사전 등록 (2026-11-02, 실행 전)

**질문:** 원시 입력 축 중 무엇이 덱 순위를 바꿀 만큼 큰가 — 큰 축은 조합 탐색 안에서(R3), 작은 축은 후처리로.

**판단(사전 등록, 임시 기준):** 축 a가 **큰 축** ⟺ ① 시즌 상위 100 밖 표본 중 그 축 하나만으로 T를 넘는 비율 ≥ **x = 5%**, 또는 ② 축 이득 중앙 ≥ **y**.
y는 결과 전에 공식으로 정한다: **y = 시즌마다 (바탕 100위 값 ÷ 150위 값 − 1)의 10시즌 중앙** — 「이 정도 이득이면 덱이 50계단 오른다」. 기대값 모드라 같은 요청의 흔들림(시드 잡음)이 없어서, 사용자 확인 때 적은 「흔들림」 대신 순위 간격을 쓴다(바뀐 점).
큰 축 → R3에서 조합 탐색 안에 넣을 후보. 작은 축 → 후처리. 가설(초안): burst_who는 크고 click · cover는 작다 — 결과로 정한다.
보조(판단 밖): 층별(상위 100 · 중간 · 아래 · 랭커) 이득, 축별 90백분위 · 최대, 어느 선택지가 가장 많이 이기나.
한계: 축 안에서도 선택지 하나만 바꾼다 — 같은 축의 여러 니케 조합(예: 엄폐 5명)은 재지 않아 그 축 이득을 낮게 본다. R3에서 큰 축은 조합으로 찾는다.
**R2 뒤:** R3 · R4 설계와 예산은 사용자 확인을 받는다(확정 사항). R1의 v3 후보(충전 창 톡톡이 4.0 · 등급 상)도 그때 함께 정한다.

**버충 택틱이 원시 선택지보다 나은 이유(문서 · 확인):** 택틱 = 충전 창 톡톡이 **4.0회/초** + 정책 C(풀버스트 끝나기 전 재장전 완료) + 등급 상. P에는 같은 원시 입력(충전 창 톡톡이 · `fb_end − 재장전` 엄폐 · 카메라)이 따로 있지만 톡톡이 속도를 3.6 하나로 두었다. **빠진 것은 어휘가 아니라 값(속도 4.0)과 등급**이다 → v3 후보: 충전 창 톡톡이 4.0 · 등급 상(R2 뒤 — 등록대로).

**해석:** 원시 입력 + 일반 사건으로 레이어 14명의 규칙 대부분이 같은 값으로 옮겨진다(미란다 · 츠바이 · 토브 전담 = 단계 i번째 우선, 프리카 + 민트 = 첫 사이클만, 마스트 3의 배수 = 3사이클 주기, 길티 · 신 · 라푼젤 = 0~2.2초 홀드 시퀀스, 밀크 = 판정 + 톡톡이 + 풀차지 섞기, 에이다 · 아인 = 본인 풀버스트 홀드). 남은 것은 ① 400평가 탐색의 흔들림(메뉴 v1 → v2로 커지며 v1에서 통과한 3덱이 떨어졌다), ② 버충 묶음의 값 · 등급, ③ 마스트 불규칙 목록이다. 계산기 요청 칸이 모자란 사례는 없었다(「확인할 것」의 `burst_sequence` 불필요).

## 원칙

1. **탐색 변수는 원시 입력과 일반 사건뿐이다.** 원시 입력은 계산기 L0 여섯 개(nikke-calc `docs/CONTROL.md` §L0 — `click` · `cover` · `cover_all` · `focus` · `burst` · `aim`)다.
   「언제」는 캐릭터와 무관한 전투 사건으로 적는다(풀버스트 시작 · 끝, 단계 열림, 쿨 복귀, 재장전 · 남은 장탄, 자기가 건 버프의 시작 · 끝).
   니케 이름이 붙은 규칙 · 카탈로그(`char_defaults.json` `_rules` · `_burst_patterns`)와 정책 이름(장전컨 A~D 등)으로 탐색 공간을 정의하지 않는다.
   출발점은 레이어를 끈 계산기 자동(`operation.auto: true`)이다.
2. **축의 크기는 정하지 않고 잰다.** 어느 축을 조합 탐색 안에서 볼지(큰 축), 후처리로 둘지(작은 축)는 측정 규칙이 정한다.
   신캐 갱신 때 같은 측정을 다시 돌린다 — 갱신 절차의 일부다.
3. **계산기 기본 레이어는 비교 기준이다.** 레이어를 켠 판(지금 절차)과 나란히 재되 탐색에 쓰지 않는다.
4. **실전 덱별 딜은 평가에만 쓴다.** 탐색 · 문턱 조정에 섞지 않는다. 랭커 육성 · 보스 패턴 · 코어가 다르므로 시즌 안 순위 상관으로만 본다.

## 표현 — 원시 입력 + 일반 사건 (회차 1에서 확정)

계산기 요청 v2가 이미 받는 칸으로 적는다(계산기 수정 불필요 — 예외는 아래 「확인할 것」).

| 원시 입력 | 요청 칸 | 일반 사건 어휘 · 파라미터 |
|---|---|---|
| `burst` 버튼 | 배치 순서, `chars.<니케>.control.burst.pattern`(사이클 목록), `.delay`, `.wait_own_cooldown`, `operation.no_burst` | 단계별로 사이클마다 누가 누르나. 일반 정책 족: 선두 고정 · 앞에서부터 쿨 된 니케 · k사이클 교대 · 특정 사이클 전담 · 쓰지 않음 — 니케 이름 없이 「단계 후보 중 i번째」로 적는다 |
| `click` 누르기 · 떼기 | `control.click`(mode tap · hold · auto + window · anchor) | 풀버스트 창(자기 · 전체), 버스트 충전 구간, 앵커 + offset |
| `cover` 시작 · 끝 | `control.reload` · `control.cover`의 앵커 표기(`fb_end` · `next_fb_start` · `own_buff_end` + offset · minus) | 정책 이름 대신 앵커 표기만 쓴다 |
| `cover_all` | `control.sequence` | 사건 기준 구간 |
| `focus`(카메라) | `operation.camera` | 니케 하나 |
| `aim` | — | 허수아비라 제외(2차 목표에서) |

- **확인할 것:** 「이 사이클은 반드시 이 니케」를 강제하는 `burst_sequence`가 요청 v2에 없다. 니케별 사이클 목록은 차례가 아닌 니케도
  앞사람이 다 쿨이면 나가게 둔다. 대부분은 사이클 목록 + 배치 순서 + `no_burst`로 표현되지만, 회차 1 표현력 시험에서 모자라면
  계산기에 요청 칸을 더하는 것을 별도 과제로 올린다.
- 시각 단위 원시 시퀀스 전체(180초 × 5명 × 프레임)는 탐색하지 않는다. 사건에 묶은 파라미터로 줄이고, 그걸로 안 되는 경우만 `sequence`로 찍는다.

| **R3 큰 축을 조합 탐색 안으로** | 큰 축을 덱 평가 안에서 같이 찾으면 같은 예산에서 더 나은가 | 시즌 4개(S36 · S39 · S41 · S42 — 영향 큰 시즌과 작은 시즌). A = 지금 절차(레이어 켬 → 후처리), B = 덱 평가 때 큰 축만 작은 내부 탐색 k회 → 후처리는 작은 축만. 같은 총 시뮬 | 5덱 합 · 실전 순위 상관 · 랭커 5덱 대조(V_top · J) 중 둘 이상에서 B가 앞서면 B를 기본으로. 신캐 모사: 레이어 대상 14명을 규칙 없는 신캐로 보고 B가 그 덱을 찾는가 | 시즌당 3~4만 |
| **R4 작은 축 · 전체 재검증** | 원시 메뉴 후처리가 지금 JT 400을 대신하나, 새 절차로 1차 목표가 유지되나 | 작은 축 후처리를 원시 메뉴로 교체, 실험 21 계정 u1~u8 · 실험 31 10시즌 재실행 | 실험 21 기준(큰 예산 참조 대비 98% 등)을 새 절차로 다시 | 약 30만 |

- R3의 내부 탐색 비용은 같은 단계 후보가 둘 이상인 덱(S42 기록의 41%)에만 붙인다. 정책 족 열거(단계 후보가 적어 가능)와
  일반 국소 탐색을 둘 다 시험한다. 덱마다 k를 줄이는 방법(대리 모델 · 가지치기)은 R3 결과를 보고 정한다.
- 시간(4코어 컨테이너 하나, 0.2초/시뮬 · 약 20시뮬/초): R0 수 분 · R1 약 30분 · R2 약 15분 · R3 시즌당 약 30~40분 · R4 약 4시간.
