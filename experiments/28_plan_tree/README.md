# 실험 28 — 5덱 편성안의 큰 분류 · 세부 분류: 기존 기록으로 계층을 만들어 본다(시뮬 0)

> 사용자 구상(2026-11-01): 편성안을 **큰 분류로 나누고, 그 안을 세부 분류로 또 나눈다.**
> 실험 25 · 27 기록(w1~w8)만으로 이 계층을 만들면 계정마다 큰 분류 · 세부 분류가 몇 개 나오고, 몇 %인가?

**상태: 완료(2026-11-01) — 관찰(시뮬 0, 판정 없음).**
- 사용자 결정(2026-11-01): 큰 분류는 J로 나눈다. 큰 분류 2~3개, 세부 분류 2~3개를 보여 주고, 계산이 크게 늘지 않으면 더보기로 더 많이 보여 준다.
  세부 분류는 1~2명 옮기기 · 바꾸기, 4덱은 그대로 두고 덱 하나만 다른 덱으로 바꾸는 것까지다.
- 주력 딜러 개념은 쓰지 않는다.

## 정의

[`tree28.py`](tree28.py).

- **값:** 구성마다 max(기본 레이어, 알려진 운용 값)이다. 운용 값은 실험 25 · 27 운용 탐색 기록에 있는 것만 쓴다.
- **큰 분류(대표끼리 J ≤ 0.2):**
  - A = 최선 5덱(실험 25 P 판, 후처리 뒤)
  - B = 실험 27 대안(A와 J ≤ 0.2, 근처 탐색 + 후처리 뒤)
  - C = A · B **둘 다와** J ≤ 0.2인 5덱 중 합 최대. 기록(실험 25 계정 탐색 + 실험 27 근처 탐색)에서 고르기만 했다. **후처리 전**이다.
    - 고르기는 기준마다 공유 쌍 예산(16)을 따로 지키는 분기 한정이다. 8개 모두 정확해다.
    - 가중합 하나로 묶어 푸는 방법(첫 시도)은 두 조건을 함께 맞추지 못했다.
- **세부 분류:** 대표에서 덱 1~2개만 바뀌고(나머지 3~4덱 그대로), 대표와 J ≥ 0.5이며, 합이 최선의 97% 이상인 5덱.
  - J ≥ 0.5에 드는 것: 맞교환 1번(0.72) · 2번(0.52), 덱 하나 통째 교체(0.67), 1명 교체(0.85) · 2명 교체(0.72).
  - 빠지는 것: 맞교환 3번(0.35) 이상.
  - 표에 보일 3개는 **바뀐 덱이 서로 겹치지 않게** 합 큰 순으로 골랐다. 그냥 합 순이면 가장 약한 덱의 1명 교체만 몰렸다.
  - 더보기는 합 순 20개까지다. 계정당 400개에서 자른다.
  - 대표 덱은 대표의 값(후처리 뒤)을 쓴다. 새로 들어간 덱은 운용 값이 없으면 기본 레이어라 **세부 분류 값은 낮게 잡힐 수 있다**(표에 「후처리 안 된 새 덱」 수를 적었다).

**관찰:**

1. **큰 분류 A의 세부 분류는 계정마다 많다(36~400개 이상).** 덱 하나의 1명 교체가 대부분이고, 덱 두 개 사이 맞교환과 덱 하나 교체도 섞여 있다.
   - 예(w7 A): ① 4덱 레오나 → 길티 99.3%, ② 5덱 벨벳 · 헬름 → 라플라스 · 이브 98.9%, ③ 3덱 레이븐 → 루드밀라 98.8%.
2. **B의 세부 분류는 B가 97%를 넘은 6개 계정 모두에서 3개 이상이다.** w1 · w3은 B 자체가 97% 아래라 0개다.
3. **C는 후처리 전 값으로 1/8만 97% 이상이다(중앙 94.9%).**
   - 같은 후처리 전 기준에서 B는 실험 27 근처 탐색 뒤 중앙 95.0%였다. 그 뒤 후처리가 중앙 +2.7%p를 더했다.
   - C에도 근처 탐색과 후처리를 하면 97%를 넘는 계정이 늘 수 있다. 이 실험은 그것을 재지 않았다(가설).
4. **C의 세부 분류가 C 대표보다 높은 계정이 있다**(w1 · w7 · w8 등). 덱 두 개를 바꾸면 A · B와의 J 제한이 풀린다.
   - 예(w7): C의 2 · 5덱을 바꾸면 98.7%다. 그 안에 A의 토브 덱이 그대로 들어간다.
   - 이런 안은 C에 가장 가깝지만 A에도 꽤 가깝다. 보여 줄 때 「다른 대표와의 J」를 함께 적는 것이 좋다.
5. **계산량:**
   - 큰 분류 고르기 · 세부 분류 나열은 시뮬 없이 계정당 수 초 ~ 20초다. 더보기를 늘려도 시뮬은 늘지 않는다.
   - 시뮬이 드는 것은 두 가지다.
     - C를 제대로 만들기: 근처 탐색 + 후처리, 계정당 약 2,500(실험 27의 B와 같은 비용)
     - 보이는 세부 분류의 새 덱 후처리: 계정당 새 덱 최대 8개 × 400 ≈ 3,200
   - 더보기 목록은 후처리 전 값으로 두면 시뮬이 들지 않는다.

## 한계

- C와 세부 분류의 새 덱은 후처리 전 값이다. 순위가 후처리 뒤에 바뀔 수 있다.
- 세부 분류는 대표에서 덱 1~2개만 바뀐 것만 센다. 네 덱에 걸친 맞교환 2번(J 0.52)은 빠진다.
- 기록 안의 구성만 쓴다. 기록에 없는 덱은 나오지 않는다.
- 계정 8개 · 허수아비 보스 · 시뮬 안의 값이다.
