# 실험 27 — J ≤ 0.2 대안 + 대안 근처 1,000평가 + 후처리: 실험 25 계정에서도 97%에 닿는가

> 실험 26은 개발 계정 12개에서, J ≤ 0.2 대안 근처를 1,000평가 더 탐색하면 96.4% → 98.5%(12/12 ≥ 97%)임을 보였다. 다만 후처리 전 값이었다.
> **이 방법을 개발에 쓰지 않은 실험 25 계정 w1~w8에 붙이고, 같은 후처리(큐브 · 컨트롤 고정점)까지 하면 그대로인가?**

**상태: 완료(2026-11-01) — 판단(사전 등록): 통과(6/8).** 계획 · 기준은 결과 전에 커밋했다(`607e564`).
- 출처: 2026-11-01 사용자 결정. 실험 25 · 26 뒤 이전 세션의 추천 「J ≤ 0.2 + 대안 근처 1,000회 탐색 + 후처리를 새 계정에서 검증」이다.
- 사용자 선택(2026-11-01): 계정은 w1~w8을 다시 쓴다. 판정 문턱은 실험 25와 같다. θ = 0.2만 재고 대조는 돌리지 않는다.
- 사용자 지시: 주력 딜러 개념은 쓰지 않는다.

## 왜 이것인가

- 유력 대안의 공식 정의는 「최선과 J ≤ 0.3 · 97% 이상」이다(2026-11-01). 근거인 실험 25는 6/8로 문턱에 걸린 통과였다.
- θ = 0.2(니케 11명 안팎이 다른 덱으로)는 탐색 없이 고르기만 하면 후처리 뒤에도 96.3%(2/8)였다.
- 실험 26에서 그 부족분은 「대안 근처를 탐색하지 않아서」로 보였다. 이것이 개발에 쓰지 않은 계정과 후처리 뒤에서도 맞으면, J 0.3보다 더 다른 대안을 안정적으로 낼 수 있다.

### 계정 — w1~w8 (실험 25와 같음)

- 이 탐색 방법(실험 26)을 만들거나 다듬는 데는 쓰지 않은 계정이다.
- **다만 실험 25에서 이 계정의 θ = 0.2 결과(탐색 없음, 96.3% · 2/8)를 이미 봤다.** 그래서 완전히 새 계정보다는 약한 검증이다(한계에 적는다).
- 실험 25의 계정 탐색 기록 · 최선 후처리 · 운용 탐색 기록을 그대로 쓴다.
  - 최선은 실험 25 운용 기록으로 다시 돌려 확인했다. 8개 모두 같은 5덱 · 같은 합, 시뮬 0회였다(결과와 무관한 사전 확인).

## 절차

[`run27.py`](run27.py).

1. **최선 = 실험 25 P 판 그대로.** 계정 탐색 U4_3000 → 5덱 고정점 후처리(JT 400). 이 후처리 뒤 최선 5덱이 **J의 기준(고정)**이다.
2. **대안 근처 탐색 1,000평가(실험 26 절차, 기본 레이어):**
   - 875평가는 라운드(100평가)로 돈다. 라운드마다 그때 기록에서 다음 대안을 고르고 고친다.
     - 고르기: 기준 5덱과 J ≤ 0.2인 5덱 중 합 최대. 값은 max(기본 레이어, 알려진 운용 값)이다(실험 25 J 상한 묶기와 같은 값).
     - 고치기: 5덱 고치기(한 명 바꾸기 · 두 덱 맞교환) 70%, 대안 덱 이웃(한 명 바꾸기) 30%. 고친 뒤도 기준과 J ≤ 0.2. 순서는 대리 모델 예상 이득 순.
   - 끝 125평가는 마지막 대안 덱의 배치 순서 다듬기다.
   - 실험 26과 다른 점은 하나다. 실험 26은 그때 기록의 기본 레이어 최선을 기준으로 다시 골랐고, 여기서는 후처리 뒤 최선(고정)이 기준이다.
3. **후처리:** 늘어난 기록으로 실험 25와 같은 J 상한 묶기 고정점 후처리(`policy_pf(packer = jpacker(θ = 0.2))`)를 돈다.
   - 출발 운용 값은 최선 후처리의 것이다. 실험 25 θ = 0.2 대안과 같은 출발이다.
   - 운용 탐색은 실험 25 기록에 있으면 다시 쓴다(결정론, 시뮬 0). 없는 것만 새로 돈다.

**관찰:**

1. **대안 근처 탐색은 8개 모두에서 대안을 올렸다.** 실험 25의 탐색 없는 θ = 0.2 대비 중앙 +1.65%p(+0.3 ~ +2.5%p)이고, 97% 이상은 2/8 → 6/8이다.
   - 탐색이 올린 몫(후처리 전)은 중앙 +1.6%p다. 후처리가 더한 몫은 중앙 +2.7%p로, 실험 25 θ = 0.2의 후처리 몫(+2.7%p)과 같다. 탐색 이득이 후처리 뒤에도 그대로 남았다.
   - 실험 26(개발 계정, +2.1%p)보다는 탐색 이득이 조금 작다.
2. **결과는 J ≤ 0.3(탐색 없음)과 비슷한 수준이다.** 중앙 98.2% 대 98.6%, 둘 다 6/8이다. J는 0.19(바꿀 10~12명) 대 0.28(8~10명)로 더 다르다.
3. **w1 · w3이 빠졌다(96.3% · 96.6%).** w3은 실험 25 θ = 0.3에서도 96.6%로 빠진 계정이다(육성 · 장탄 · 큐브 레벨 무작위).
4. **새 대안 덱의 이웃 수**(기록 안에서 4명 이상 같은 구성)는 계정별 중앙 4~76에서 88~264로 늘었다. 실험 26과 같은 모양이다.
5. **대안 쪽 탐색이 최선을 올린 계정은 w2 하나다(+1.62%).** 오른 최선 기준으로 다시 재도 6/8이다.
6. **비용:** 계정당 대안 근처 탐색 약 890평가, 후처리 운용 탐색 4~5구성(새로 돈 것 2~5개, 새 시뮬 800~1,800)이다.
   실험 25 θ = 0.2 대안(후처리만, 400~2,000)보다 계정당 약 1,000~1,500 시뮬이 더 든다.
   탐색 예산 1,000 중 약 110은 쓰지 않았다. 끝의 배치 순서 다듬기에서 남은 새 순서가 125개보다 적었다(실험 26과 같다).

**해석:** 「J ≤ 0.2 + 대안 근처 1,000평가 + 후처리」는 개발에 쓰지 않은 계정 8개 중 6개에서 97% 이상인 대안을 냈다. 사전 등록 기준은 통과했지만 문턱에 걸렸다.
탐색은 모든 계정에서 대안을 올렸고, 결과는 J ≤ 0.3 대안과 비슷한 값에 더 다른 묶음이다. 비용은 계정당 시뮬 약 1,000~1,500이 더 든다.
유력 대안 절차로 쓸지(공식 정의 J ≤ 0.3을 바꿀지)는 사용자가 정한다.
