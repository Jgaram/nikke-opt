# 실험 39 — 후보 생성 고치기: (a) 묶음을 아는 후보 생성 · (b) 탐험 몫

> 실험 38 1단계: 우리 탐색이 랭커 덱을 못 가 보는 곳은 「다음에 무엇을 계산할지 고르기」다. 놓친 몫 대부분은 우리가 계산한 덱에서
> 같은 단계 한 명만 다른 랭커 덱인데, 그 이웃의 부모 덱은 값 순위가 낮아 한 명 교체 대상(값 상위 40 · 최선 5덱)이 아니었다.
> 대리 모델도 그 덱을 실제의 중앙 74%로 본다. 실험 38 [다음 방향](../38_ranker_miss/README.md#다음-방향-판단-수정-후-재검증--구체적-문제-확인-사용자-확인-전)의 (a) · (b)를 고쳐서
> 실험 38에 쓰지 않은 시즌에서 지금 절차와 견준다.

**상태: 끝(2026-11-03) — 판정 a · b 모두 「비김」, G가 줄지 않아 사전 등록대로 둘 다 중단.** [결과](#결과-2026-11-03)

## 사용자 지시 (2026-11-03)

- 「(c)는 탐색에 랭커 조합을 쓰겠다는 거 같은데 우리가 하려는 것과 맞지 않지 않나?」 → (c)(랭커 덱 넣고 이어 찾기)는 뺀다.
  (c)는 진단이고, 랭커 덱을 입력으로 쓰므로 랭커 없이 찾는 목표에 직접 도움이 안 된다. 「한 번 계산하면 묶음에 들어간다」는 정확한 묶기라 1단계에서 이미 보였다.
- 「각각의 방향이 독립적이라면 각각 세션 열어서 진행해」 → 확인 질문 답: **세션 3개(기준선 · a · b)**, 검증 시즌 **S23~S32 10시즌**.

## 판(arm)

세 판은 실험 10 `run_method` G+E(= 실험 36 A 사전 계산)에서 **라운드마다 새로 계산할 구성을 고르는 `local_round`만** 다르다.
설계 · 구성 · 킥 · 순서 다듬기 · 예산 · 난수 시드는 같다. 지금 `local_round`: 한 라운드 100평가 = ⓐ 최선 5덱 고치기(덱 하나의 같은 단계 한 명 교체 · 두 덱 맞교환, 모델 예상 이득 순, 70) + ⓑ 값 상위 40 구성마다 같은 단계 한 명 교체 이웃 중 모델 예측 상위 8개를 모아 예측 순(30).

| 판 | 바꾸는 것 | 소유 |
|---|---|---|
| base | 바꾸지 않음(실험 10 `local_round`) | 기준선 세션 |
| **a 묶음을 아는 후보 생성** | ⓑ의 부모를 「값 상위 40」에서 넓힌다 — 상위 대안 5덱들(지금 최선 5덱과 겹침 제한으로 뽑은 다음 5덱들)에 든 덱 · 지금 최선 5덱이 안 쓰는 니케로 짠 덱까지. 놓친 랭커 덱은 하나씩은 중간 값이고 묶음으로 강하다 | 세션 A — `arm_a.py` |
| **b 탐험 몫** | 라운드의 일부를 대리 모델 순위 밖에서 고른다(예: 불확실성 보정 · 무작위 같은 단계 한 명 교체). 모델이 못 보는 시너지 점프를 시뮬로 시험한다 | 세션 B — `arm_b.py` |

- 인터페이스(고정): `local_round(sess, n, lineage, fitf) -> list[tuple]` — `arm_a.py` · `arm_b.py` 머리말 참고. 라운드 평가 수 n은 그대로다(같은 예산).
- 세부 설계(부모를 몇 개 · 어떤 덱으로, 탐험 몫 비율 · 고르는 법)는 각 세션이 개발 시즌에서 정하고 `PARAMS`와 이 문서 §판 설계에 적는다.
- (a) + (b) 함께는 이번에 돌리지 않는다. 둘 다 「좋음」이면 다음 회차 후보.
