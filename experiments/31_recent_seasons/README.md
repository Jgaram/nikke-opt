## 절차 ([`run31.py`](run31.py))

시즌마다:

1. **B_s0 · B_s1** — 실험 10 `run_method(G+E)` 예산 12,500, 시드 0 = 계정 id `pre-S<시즌>`, 시드 1 = `pre-S<시즌>-s1`(실험 30과 같은 예산 · 절차).
   실험 30 전격에서는 끝 순서 다듬기에서 예산을 다 쓰지 않고 시드마다 약 11,000평가에서 끝났다.
2. **W**(`USE_W`일 때만) — 실험 30 `run_wide`. 넓게 찾기 예산 = B 두 시드가 실제로 쓴 평가 수 − 앞부분(실험 30 `w_budget_of`, 2026-11-01 변경 `3d8bd72`).
3. **코어 30** — 실험 30 `corecheck`의 RC를 시즌 계정으로(`core_rc`): 코어 없음 지도의 후보 2,000개(`core_candidates`: 지도 대표 덱 + 대표 5덱의 덱 자리마다
   바꿔 넣을 구성)를 코어 30 + 시즌 options로 다시 평가하고, 그 위에서 코어 30 이어 찾기 2,000평가(`continue_search`, 끝 1/8 순서 다듬기).
   - 근거(실험 30 `corecheck`, 같은 시즌 코어 30으로 따로 찾은 최선 대비): 재평가만(R)은 S40 99.9% · **S34 97.9%**, 이어 찾기까지(RC)는 S40 99.98% · S34 100.0%.
     실험 30의 관찰 기준 「두 시즌 모두 99% 이상이면 합쳐도 된다 쪽」을 채운 것은 RC다. 그래서 재평가만이 아니라 RC를 쓴다(`run31.CORE_CONT` = 2,000).
4. **members** — 두 보스 지도의 큰 분류 대표 덱을 다시 평가해 니케별 딜을 남긴다(덱당 1시뮬, 화면용).
5. **rankers** — 랭커 대표 5덱 · 1위 5덱 · 상위 40 스쿼드(가장 흔한 순서)를 두 보스로 평가한다(실험 22와 같은 모양).
6. **analyze**(시뮬 0) — 보스마다:
   - **큰 분류** = 실험 30 `class_map`: A = 최선, 다음 = 앞 대표 모두와 J ≤ 0.2인 겹치지 않는 5덱 중 합 최대, 최선의 95% 아래면 멈춤(최대 10개).
   - **세부 분류** = 실험 28 `subs` · `order_subs`: 대표에서 덱 1~2개만 바뀌고 대표와 J ≥ 0.5, 합 ≥ 최선의 97%. 3개를 보이고 더보기 20개(400개에서 자름).
   - **랭커 대조**: 실험 22 지표(N25 · D4 · V_top · V_r1 · V_pack)를 A 기준으로, 랭커 대표 5덱 · 1위 5덱과 큰 분류마다의 J.

사용자가 사이트에서 보고 로직 개선 여부를 정한다. 결과를 보기 전에 함께 적어 둘 관찰 항목:

- 시즌마다 97% 이상 큰 분류 수, 큰 분류 비율, 세부 분류 수(보스마다).
- 랭커 대표 5덱 · 1위 5덱이 어느 큰 분류에 가까운가(J), 그 J가 세부 분류 범위(0.5 이상)에 드는가.
- N25 · D4 · V_top — 실험 22(최근 4시즌: N25 중앙 21, V_top 중앙 96.4%)와 같은 수준인가.

## 실행

```bash
bash tools/setup_evaluators.sh
R=experiments/31_recent_seasons/run31.py
# 1. B: 시즌마다 시드 둘을 프로세스 둘로(4코어면 시즌 둘씩 동시에)
for s in 33 34; do for p in B_s0 B_s1; do
  (source .cache/evaluators.env && python $R run --season $s --part $p > .cache/exp31_S${s}_$p.log 2>&1) &
done; done; wait
# 2. (USE_W일 때) W → 3. 코어 30 재평가 → 4. members — 시즌마다 차례로, 시즌끼리는 동시에

python $R analyze && python web/build.py --out _site
```

- 시뮬 수는 부분별 기록(`part_*.json`의 `sims`)으로 남긴다. 부분 하나가 끝날 때마다 커밋 · push해도 된다(사이트는 `analysis.json`만 읽으므로 analyze 전에는 「실행 중」).
