# 실험 36 — 최근 10시즌 현황판 다시 계산

> 실험 31(최근 10시즌 S33~S42 편성안 지도)을 지금 평가기와 실험 32 · 35에서 정한 절차로 다시 계산해 현황판 사이트를 갱신한다.
> 판정 없음(운영 실행) — 사용자가 사이트를 보고 판단한다.

**상태: 실행 중(2026-11-02).**

## 사용자 지시 (2026-11-02)

순서: 실험 32 B′ 비열등 재검증 → 실험 35 장비 옵션 → **이긴 절차로 10시즌 계산 후 사이트 갱신**. 단계가 목표에 못 미치면 그 단계를 고쳐 다시 돌린다.
후처리에는 컨트롤 · 장비 옵션 · 큐브를 모두 넣는다(사용자 질문 「컨 옵션 큐브 모두 고려하면 순서가?」에 「셋 다 최종 5덱 후처리」로 답하고 큐브도 넣겠다고 알림).

## 절차 (실험 32 · 35 판단으로 정함)

| 단계 | 내용 | 근거 |
|---|---|---|
| 사전 계산 | 실험 31 B 판 그대로: 실험 10 `run_method` G+E, 시드 s0 · s1 × 12,500, 풀 = 그 시즌 출시 니케, 보스 속성 · 그때 없던 애장품 0단계, **레이어 켬(A)**, 장비 옵션 = 계산기 기본 스펙 | [실험 32 결론](../32_primitive_control/README.md#r3d-결과와-비열등-재검증-결론-2026-11-02): 사람 규칙 없는 B′ · 수정 1 · 수정 2 모두 비열등(δ 1%) 미달 → A 유지 |
| 지도 · 분류 | 실험 31과 같다(실험 30 `class_map`, 큰 분류 J ≤ 0.2 · 세부 분류) | |
| 코어 30 | 실험 31과 같다(코어 없음 후보 2,000 재평가 + 이어 찾기 2,000, RC) | |
| **후처리(새로)** | 코어 없음 최선 5덱마다 ① 컨트롤 + 큐브(실험 6 메뉴 = R1 L + 큐브 전부 Lv15, 레이어 위, M3:k2 400) → ② 장비 옵션 12줄(실험 35 O, 400) → ③ ②의 배분 위에서 컨트롤 + 큐브를 ①의 선택부터 다시(400). 값 = ② · ③ 중 높은 것 | [실험 35 R0](../35_equip_options/README.md#r0-결과-2026-11-02): 큰 축(+17%) · 최종 5덱 후처리로 충분(loss 0.09%) · 옵션 뒤 컨트롤 한 번 더(+0.40%) |
| 랭커 덱 · 덱별 니케 딜 | 실험 31과 같다(레이어 1시뮬, 두 보스) | |

- 평가기: nikke-calc-rs `8bc51a2`(원본 nikke-calc `67835ca` 포팅). 실험 31은 옛 평가기(`5bb2cb0`)라 값을 그대로 견주지 않는다.
- **S36 · S39 · S41 · S42의 사전 계산은 실험 32 R3 A 기록을 옮겨 쓴다**(같은 평가기 · 같은 절차 · 같은 계정 id). 나머지 6시즌은 새로 돈다.
- 큐브: 출발 = 렐릭 베어 큐브(기본 스펙), 후보 = 평가기가 지원하는 큐브 전부 Lv15(실험 17 `cubes.py`). 실험 17 운용 JT는 사전값으로 큐브를 줄였지만 여기서는 전부 둔다.
- **값의 기준이 둘이다:** 지도 · 분류 · 랭커 대조는 사전 계산 값(장비 옵션 8줄 · Lv10 기본 스펙), 후처리 값은 12줄 · Lv11 옵션 + 컨트롤 + 큐브다. 사이트에 따로 보인다.
- 코어 30은 후처리하지 않는다(지도만).
