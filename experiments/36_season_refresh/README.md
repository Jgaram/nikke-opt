## 랭커 덱 후처리 (사용자 요청 2026-11-03)

> 「혹시 지금은 우리 예상한 A만 후처리 중이지? 비교를 위해 랭커 대표덱과 랭커 최선덱도 후처리한 후에 보여줄 수 있을까?」
> 확인 질문 답: 최선덱 = **③ 랭커 스쿼드로 짠 최선 5덱**, 순서 = **남은 시즌(우리 A) 먼저**, 그다음 랭커 후처리.
> 이어서(같은 날) 「우리계산기로 … 같은 후처리로 비교했을 때 우리쪽이 100억씩 큰 거 같아서 … 사이트에 보이는 랭커딜량은 후처리 된게 맞아?」 → 랭커 칸은 사전 값이었다. 답: **랭커 칸을 후처리 값으로 + 랭커 1위 5덱도 후처리**.

- 묶음 셋(코어 없음만):
  - **top**: 랭커 대표 5덱 — 상위 300명이 5덱을 그대로 가장 많이 쓴 묶음(seasons.json `top_five`).
  - **pack**: 랭커 스쿼드로 짠 최선 5덱 — `rankers.json` 코어 없음 사전 값(대표 · 1위 · 상위 40 스쿼드)으로 겹치지 않게 묶은 합 최대(화면의 V_pack 묶음).
  - **r1**: 랭커 1위 5덱(seasons.json `rank1`) — 나중에 더함, 앞 두 묶음의 덱 기록은 그대로 쓴다.
- 후처리는 우리 A와 **똑같다**(`run36.post_deck`: ① 컨트롤 + 큐브 → ② 장비 옵션 12줄 · Lv11 → ③ 컨트롤 + 큐브 다시, 각 400평가, 최종 = ② · ③ 중 높은 것). 덱 순서는 랭커 순서 그대로.
- 같은 순서의 같은 덱은 한 번만 돈다(두 묶음이 덱 1~3개를 함께 씀 · 우리 A 후처리에 이미 있으면 그 기록). 지원하지 않는 니케가 든 묶음은 계산하지 않는다.
- 비교 = 후처리 뒤 5덱 합끼리(랭커 ÷ 우리 A). 랭커의 실전 육성 · 컨트롤이 아니라 「같은 조건으로 다듬었을 때」의 값이다.
- 예산: 시즌마다 서로 다른 랭커 덱 9~14개 × 1,200, 10시즌 14만.
- 코드: [`rpost36.py`](rpost36.py) → `run_log/S??/rpost.json` · `post/S??-r<j>.json`. `run36.py analyze`가 줄마다 `rpost`로 넣고, 사이트는 코어 없음에서 「그 시즌 랭커」 칸(세 묶음 격자 · 우리 A 대비 %) · 개요 표 「랭커 ÷ 우리 A」 · 요약 타일을 후처리 뒤끼리 보이고(사전 값은 작게), 후처리 칸 아래에 비교 타일을 둔다. 코어 30은 사전 값끼리.
- 사전 값만으로도 S36 · S42는 랭커 쪽이 우리 A보다 높다(S36 대표 278.9 · 최선 283.9 대 우리 A 261.8억, S42 최선 312.1 대 299.4억).

### 사용자 질문: Shift가 여러 니케에 겹치나 · 카메라를 옮길 때 재장전 (2026-11-03)

> 「shift들 여러 캐릭 겹치는 것처럼 보이는데 맞나? 실제로는 카메라 잡은 니케만 shift 가능 … 다른 캐릭으로 옮기는 순간 다른 캐릭이 엄폐로 들어가고
> 기존에 보던 캐릭은 재장전을 멈추고 다시 싸우기 시작하겠지. 그런 규칙인가?」

- **Shift끼리 겹친 곳은 167덱에서 0번이다.** 평가기는 조작권(카메라)을 가진 니케만 엄폐 정책을 연다(`cover.rs` `apply_cover_policy`의 `owns`).
  겹쳐 보인 것은 서로 다른 니케의 Shift가 틈 없이 이어진 곳(조작권이 엄폐 중인 니케에서 다른 니케의 장전컨으로 바로 넘어감 — 예: S42-4 아인 25.15~25.73초 → D 25.73~27.15초)과 짧은 구간 최소 폭 3px이다.
- 실제로 겹치는 것은 「한 니케 좌클릭 + 다른 니케 Shift」 136곳(중앙 0.1초, 최대 1.6초)뿐이고 모두 버충 톡톡이가 먼저 열린 경우다.
  긴 것은 로그 표시 문제다 — S34-r5 타키나 톡톡이 구간은 13.2~26.0초로 적히지만 실제 톡톡이는 카메라가 에이다로 간 15.9초에 멈추고, 그 뒤는 버스트 무기 사격이다(구간이 재장전 완료 때에야 닫힌다).
  → 위 「고침」의 ②로 0곳이 됐다(시각화만 — 총딜 그대로).
- **카메라를 옮길 때 규칙은 사용자 설명과 반만 같다.** 원래 니케는 바로 엄폐에서 나오지만(`release_control` → `exit_cover`), **재장전은 취소되지 않고 끝까지 간다.**
  같은 평가기에서 시간 엄폐가 끝날 때(`expire_timed_cover`)는 「탄이 남았으면 재장전 취소, 없으면 클립 뒤 취소」인데, 카메라가 떠날 때만 이 규칙이 없다.
  예: S42-4 아인은 25.73초에 엄폐에서 나왔는데 재장전이 27.17초에 끝나 다음 버충을 꽉 찬 탄창으로 시작한다.
- 영향(시험 평가기, 레포에 올리지 않음): 카메라가 떠날 때도 시간 엄폐와 같은 규칙을 적용(`control.rs` `release_control`, 9줄)하고 실험 36 덱 167개를 **같은 최종 선택지로** 다시 돌렸다.

- **사용자 확인(2026-11-03) — 게임 규칙:** 엄폐가 풀릴 때 남은 탄이 있으면 재장전을 멈추고 다시 싸운다. 남은 탄이 0이면 Shift · 클릭과 상관없이 재장전하고 사용자가 막을 수 없다
  (위 시험 평가기의 규칙과 같다 — 0발이면 클립 재장전만 한 클립 뒤 취소).
