# 실험 6 — 니케별 컨트롤 선택지와 조합 의존성 (연구 회차 1)

> 니케의 최선 컨트롤은 동료와 상관없이 대체로 같은가, 짝에 따라 바뀌는가? 조합당 몇 회의 시뮬로 찾을 수 있는가?
> 이 답으로 조합 탐색에서 컨트롤을 어떻게 다룰지(고정 조건 · 상위 후보 후처리 · 공동 탐색) 정한다.

**상태: 준비 완료 · 판단 기준 사전 등록 — 본 실행 전** (2026-10-29). 진행 방식은 [연구 회차](../../docs/SEARCH.md#연구-회차-계획--실험--해석--다음-방향-결정)를 따른다.

## 왜 이것부터

3단계(조합 + 큐브 + 컨트롤)로 가기 전에 조합 탐색의 고정 조건부터 문제다.

- **완전 오토**(`operation.auto: true`)는 수동 운용이 핵심인 조합을 과소평가한다. 예: 미란다 조합의 에이다 홀드 · 미하라 엄폐컨.
- **평가기 기본 레이어**는 니케 9명에게만 손으로 등록한 규칙이다(nikke-calc `docs/CONTROL.md` §캐릭터별 기본 컨트롤).
  등록되지 않은 니케는 이득이 있는 컨트롤도 꺼진 채로 돈다. 어느 쪽을 고정해도 임의적이다.
- 사용자 판단(2026-10-29): 니케별 컨트롤은 비슷한 경우가 많지만 조합에 따른 예외도 종종 있다.

그래서 조합 연구보다 먼저, 컨트롤을 **니케별 선택지 + 동료 조건**으로 찾을 수 있는지와 그 비용을 잰다.
평가기도 조합 비교에는 정책을, 절대 시각 시퀀스는 특정 상황 재현·디버그에 쓰라고 구분하고(§명시 시퀀스),
최적 운용을 고르는 일은 평가기가 아니라 바깥 탐색 도구의 몫이라고 밝힌다(§택틱).

## 검토한 세 방향

| 방향 | 이번 회차의 판단 |
|---|---|
| A. 컨트롤 오토 고정 + 조합 탐색 | 비교 조건(완전 오토)으로만 둔다. 고정 조건이 조합 순위를 얼마나 왜곡하는지 먼저 잰다 |
| B. 조합 몇 개 고정 + 원자 단위 컨트롤(절대 시각 시퀀스) | **보류.** 공간이 크고, 결과가 그 조합의 사이클 시각에 묶여 다른 조합·계정에 재사용하기 어렵다. 실행 가능성도 따로 검토해야 한다. 선택지로 표현되지 않는 운용이 결과에서 의심되면 해당 조합 1~2개의 상한 확인용으로 재개한다 |
| C. 조합 몇 개 고정 + 특징적 컨트롤(정책 선택지) | **이번 회차.** 니케별 선택지에서 최선을 찾고, 그 선택이 조합에 따라 얼마나 바뀌는지 잰다 |

## 조건

| 고정 | 값 |
|---|---|
| 평가기 | Rust `nikke-sim`(`nikke-calc-rs` `89d2e64` 빌드, 원본 nikke-calc `23164e4` 포팅). 준비 단계에서 원본과 대조한다 |
| 타깃 | 평가기 기본 적 = 허수아비. 패턴·속성·코어·파츠 없음, 방어력 31784(솔로 레이드 모의전 Lv 400). 1차 기준 프리셋이 정해지기 전의 임시 조건 |
| 버스트 게이지 | **`sim.burst_gauge_mode: "accumulate"`** (사용자 결정, 2026-10-29. 어댑터 기본값으로 바꿨다). 평가기 기본 `fixed`는 사이클을 캐릭터별 표 값으로 고정해 실제 게이지 충전 차이와 버충·카메라 컨트롤을 반영하지 않는다. 평가기 README는 일부 캐릭터의 고유 버스트 충전 효과가 덜 검증됐다고 밝힌다 — 결과 해석에 표시한다 |
| 기대값 모드 | `sim.expected: true` (어댑터 기본) |
| 육성 | 전원 기본 스펙 |
| 큐브 | 기본 스펙 큐브 = 렐릭 베어 큐브 Lv15(재장전 속도) 고정. 큐브 공동 탐색이 작업을 크게 늘리면 이 큐브로 고정한다는 사용자 결정(2026-10-29)에 따른다 |
| 조작 모드 | `operation.control_mode: "solo"` (평가기 기본). 조작자 1명, 전환은 자유·비용 없음, 겹치면 급한 조작이 카메라를 가져간다. 버스트 입력은 카메라와 무관하다 |
| 배치 순서 | 조합별로 선정할 때 정한 순서로 고정. 컨트롤과 배치 순서의 상호작용은 상위 조합 몇 개에서만 추가로 본다 |

**실행 가능한 컨트롤의 범위** (사용자 확인, 2026-10-29): 수동 조작은 한 번에 한 명이지만 돌아가며 조작할 수 있고,
버스트 순서·타이밍 조작은 가능하다. `solo` 모드와 버스트 축(배치 순서 · `burst.pattern` · `burst.delay` ·
`burst.wait_own_cooldown`)이 이 범위를 표현한다.

## 컨트롤 선택지 (안)

평가기 어휘(nikke-calc `docs/CONTROL.md` §설정 스키마)에서 니케 정보로 만든다. 값 격자는 준비 단계에서 확정한다.

| 축 | 대상 | 선택지 |
|---|---|---|
| 좌클릭 | 차지형(UP 입력). `DOWN_Charge` 6명 제외 | 자동 · 상시 톡톡이 · 본인 풀버스트 홀드 · 풀버스트 후 홀드 판정 |
| 장전컨 | 전 무기 | 없음 · A · B · C(`lead`·`margin` 2~3값) · 남은 탄 부족 시만(`if_dry`) |
| 버스트 엄폐컨 | 전 무기 | 끔 · 켬 |
| 탄충 취소 | 전 무기 | 끔 · 켬 |
| 버스트 | 버스트를 쓰는 니케 | 딜레이 0 · 몇 값, 자기 쿨 대기 끔 · 켬, 사이클 패턴(카탈로그가 있는 니케만) |
| 카메라 · 버충 | 스쿼드 | 카메라 기본 · 차지형 니케 각각, 버충 끔 · 담당 후보 각각 |

선택지가 의미 없어 보이는 니케(예: 엄폐컨이 아낄 발수 소모 버프가 없음)도 미리 지우지 않고 시뮬로 확인한다.

## 평가 문제 — 조합 약 30개

컨트롤 결과를 보기 전에 규칙으로 고른다. 출처는 [실험 2](../02_score_distribution/README.md)의 풀 60명과 랭커 구성이다.

- 버스트 틀(1-1-3 · 1-2-2 · 2-1-2 · 레드 후드 틀)별로 나눈다.
- 기본 레이어 대상 중 풀에 있는 9명(앨리스 · 에이다 · 미하라 : 본딩 체인 · 홍련 : 흑영 · 마스트 : 로망틱 메이드 ·
  미란다 · 츠바이 · 토브 · 프리카)이 든 조합과 없는 조합을 함께 둔다. 기본 컨트롤이 붙는 니케 중 아인 · 밀크 :
  블루밍 바니 · 길티 : 마이티 바니 · 신 : 스위프트 바니 · 라푼젤 : 퓨어 그레이스는 풀에 없다 — 필요하면 추가한다.
- 같은 니케가 서로 다른 동료와 3개 조합 이상에 나오게 한다. 니케 고유 선택인지 보려면 필요하다.
- 차지형 비중과 base 충전 시간(버충 후보 여부)이 다른 조합을 섞는다.
- 성능은 기본 레이어 기준 상·중 구간에서 고른다.

풀이 S40 랭커 정보에서 왔다는 점은 남긴다. 이번 질문의 판정에 주는 영향은 작다고 보지만 확인하지 않았다.

## 비교 조건과 탐색

| 조건 | 내용 |
|---|---|
| 완전 오토 | `operation.auto: true` — 기본 레이어까지 끈다 |
| 기본 레이어 | 운용을 주지 않는다(평가기 기본 규칙) |
| 선택지 탐색 | 기본 레이어에서 출발해 니케·축을 하나씩 바꿔 보는 좌표 하강. 개선이 없을 때까지 반복 |
| 출발점 확인 | 기본 레이어 대상 니케가 든 조합 일부는 완전 오토에서도 출발해, 알려진 운용(예: 미란다와 함께일 때 에이다 홀드)을 다시 찾는지 본다 |
| 참조 | 3~5개 조합은 무작위 재시작·추가 반복을 크게 써서 좌표 하강이 선택지 안 최선에 가까운지 확인한다 |

부산물: 같은 조합을 `fixed` + 기본 레이어로도 돌려 두 게이지 방식의 순위 차이를 남긴다. 기존 실험 2~5는 `fixed`였다.

## 예산 (추정)

조합당 탐색 100~200회로 보고, 30개면 3천~6천 회다. 참조·출발점 확인·`fixed` 비교를 합쳐 1만 회 안쪽.
Rust는 4코어에서 약 21회/초라 10분 안팎이다. 실제로 쓴 횟수를 조건별로 기록한다.

## 잴 것

1. 기본 레이어·완전 오토 대비 선택지 탐색의 이득 (조합별 분포)
2. 세 조건 사이의 조합 순위 상관과 상위권 역전 사례
3. **니케 고유성** — 같은 니케가 여러 조합에서 같은 선택지를 고르는 비율. 다른 선택이 이득을 낸 경우(예외)의 크기와,
   그 예외를 특정 동료의 유무로 설명할 수 있는지
4. 조합당 몇 회에서 탐색 최선의 99%에 닿는지 (출발점별)
5. `solo` 모드에서 카메라 경합으로 막힌 조작 (결과의 `control_detail`)

## 판단 기준 (사전 등록 2026-10-29, 본 실행 전)

본 실행 전에 관리자가 확정했다. 실행 뒤 바꾸면 원래 값과 이유를 함께 남긴다.

| 결과 | 다음 방향 |
|---|---|
| 탐색 이득이 작고(`search_from_layer`/`layer` − 1의 중앙 1% 미만) 순위가 유지됨(`layer`↔`search_from_layer` Spearman 0.95 이상, 상위 5개가 같은 집합) | 기본 레이어를 조합 탐색의 고정 조건으로 쓰고 컨트롤은 상위 후보 후처리. 조합 군집 연구(1단계)로 넘어간다 |
| 니케 고유 선택이 대부분(**실질 최빈 비율 0.8 이상**)이고 예외를 동료 조건으로 설명할 수 있음(**유의 예외의 60% 이상에 동료 조건 후보**) | **데이터 기본 레이어**(니케별 최선 + 동료 조건 예외 규칙)를 만들어 고정 조건으로 쓴다. 새 조합에서 예외를 잡는 데 드는 시뮬 수를 재고 조합 탐색에 연결한다 |
| 예외가 잦고(실질 최빈 비율 0.8 미만) 동료 조건으로 설명되지 않음(60% 미만), 또는 순위 역전이 잦음(`layer`↔`search_from_layer` 상위권 역전 3건 이상) | 컨트롤 변경을 탐색 이웃에 넣는 공동 탐색. 「니케 + 짝」 모델을 컨트롤 선택 예측에 시험한다 |
| 참조 탐색이 좌표 하강보다 크게 좋음(참조 조합 중 하나라도 `reference`/`search_from_layer` − 1이 1% 이상) | 선택지 사이 상호작용이 크다. 탐색법을 고쳐 재검증한다 |

- **용어.** 니케 고유성은 니케 단위 축(click · reload · cover · cancel · burst)의 (니케, 축) 항목마다 `search_from_layer` 최선을 본다.
  **유의 예외** = 최빈과 다른 선택 중 예외 이득(예외 최선 / 그 축만 최빈으로 바꾼 딜 − 1)이 **0.3% 이상**이거나 미측정인 것.
  0.3% 미만은 사실상 같은 선택으로 친다(기대값 모드라 잡음은 없지만, 이 크기는 다음 단계 판단을 바꾸지 않는다).
  **실질 최빈 비율** = 1 − 유의 예외 수 / 전체 (니케, 축, 조합) 수(합산).
- 동료 조건 후보가 예외 조합 하나에서만 나온 경우는 「약한 근거」로 따로 센다 — 등장 3~4회라 우연히 맞기 쉽다.
- **줄 적용 순서.** 넷째 줄(탐색법 문제)을 먼저 본다 — 해당하면 다른 줄의 판단은 보류하고 탐색법을 고친다.
  그다음 첫째 줄, 둘째·셋째 줄 순. 첫째와 둘째가 함께 맞으면 첫째(더 단순한 쪽)를 고르고 둘째의 수치를 다음 회차 참고로 남긴다.
  어느 줄에도 딱 맞지 않으면 수치를 적고 관리자가 판단 근거를 함께 쓴다.

사용자의 사전 판단(대체로 비슷하고 예외가 종종)대로라면 둘째 줄이 유력하지만, 결과로 정한다.

## 준비 작업

관리자 세션과 작업 세션의 분담·순서·점검 시점은 [세션 계획](SESSIONS.md)에 있다.

1. **Rust ↔ 원본 대조** — 컨트롤 · `accumulate` · `solo`를 쓴 요청 표본 10~20개. 차이가 크면 원본으로 돌리거나 원인부터 본다.
2. **선택지 생성** — 무기 종류 · 차지 입력 방식 · 버스트 패턴 카탈로그를 어디서 얻을지 정한다. 평가기 내부를 import하지 않는다
   ([작업 규칙](../../rules/workflow.md#저장소-경계)). 평가기 데이터를 읽기 전용 입력으로 쓴다면 출처 커밋을 기록한다.
3. **조합 선정과 기록 형식** — 선정 규칙을 코드로 고정하고, 요청 전문 · 결과 · `control_detail` · 조건 라벨을 남긴다.
