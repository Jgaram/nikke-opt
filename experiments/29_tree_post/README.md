# 실험 29 — 큰 분류 C를 근처 탐색 + 후처리로 만들고, 보이는 세부 분류의 새 덱을 후처리한다(w1~w8)

> 실험 28은 기존 기록만으로 큰 분류 A · B · C와 세부 분류를 만들었다. C와 세부 분류의 새 덱은 후처리 전 값이었다(C 중앙 94.9%, 97% 이상 1/8).
> **C에 실험 27과 같은 근처 탐색 + 후처리를 하면 셋째 큰 분류도 최선의 97%에 닿는가?** 보이는 세부 분류 값은 후처리 뒤 어떻게 바뀌는가?

## 절차

[`run29.py`](run29.py). 정의는 [실험 28](../28_plan_tree/README.md#정의)을 그대로 쓴다.

1. **A · B는 고정이다.**
   - A = 실험 25 P 판 최선(후처리 뒤)
   - B = 실험 27 대안(후처리 뒤)
2. **C 근처 탐색(기본 레이어, 1,000평가, 실험 27 절차):**
   - 출발 기록은 실험 25 계정 탐색과 실험 27 근처 탐색 기록이다.
   - 라운드(100평가)마다 A · B **둘 다와** J ≤ 0.2인 5덱 중 합이 가장 큰 것을 고르고(실험 28 `pick_far`, 기준마다 공유 쌍 16을 따로 지킨다) 고친다.
   - 고치기는 5덱 고치기 70%, 대안 덱 이웃 30%다. 고친 뒤에도 두 기준과 J ≤ 0.2여야 한다.
   - 끝 125평가는 배치 순서 다듬기다.
   - 값은 max(기본 레이어, 알려진 운용 값)이다. 운용 값은 실험 25 · 27 운용 기록 전부를 쓴다.
3. **C 후처리:** 늘어난 기록으로 5덱 고정점 후처리를 한다(JT 400, 묶기 = 두 기준 `pick_far`).
4. **세부 분류 후처리:**
   - A · B · C 대표마다 실험 28과 같이 세부 분류를 나열한다(덱 1~2개 바뀜, 대표와 J ≥ 0.5, 최선의 97% 이상). 보일 3개는 바뀐 덱이 서로 겹치지 않게 고른다.
   - 보일 3개 안의 새 덱 중 운용 값이 없는 것을 후처리하고 다시 나열한다. 최대 3번, 계정당 새 덱 16개까지다.
   - 더보기(합 순 20개까지)는 그때 값 그대로 둔다. 후처리 안 된 새 덱은 기본 레이어 값이다.
   - 세부 분류마다 다른 대표와의 J를 적는다(실험 28 관찰 4).
5. 운용 탐색은 실험 27 → 25 기록에 있으면 다시 쓴다(결정론, 시뮬 0).

## 판단 기준 (사전 등록 — 결과 전)

| 판단 | 조건 |
|---|---|
| **통과** | 후처리 뒤 C 5덱 합이 최선 5덱 합(실험 25 P 판)의 97% 이상인 계정이 **8개 중 6개 이상** |
| **미통과** | 그 밖 |

- 97% · 6/8은 실험 25 · 27과 같은 문턱이다. A · B와의 J ≤ 0.2는 만드는 방식상 늘 맞는다.
- **통과하면** 현황판에 큰 분류 3개(A · B · C)를 보여 줄 근거로 적는다. **미통과면** C는 「97% 미만이면 숨김 또는 표시」 중 사용자가 정한다.
- **관찰(판정에 안 씀):**
  - 실험 28 C(기록만) → 탐색 전 → +1,000(후처리 전) → 후처리 뒤
  - 보이는 세부 분류의 값 · 순서가 후처리로 바뀐 정도, 다른 대표와의 J
  - 큰 분류별 세부 분류 수
  - 비용(C 탐색 · C 후처리 · 세부 분류 후처리 새 시뮬)

## 예산과 실행

- 새 시뮬 예상: 계정마다 C 탐색 1,000 이하, C 후처리 약 400~2,000, 세부 분류 후처리 최대 약 6,400(새 덱 16개 × 400). 8개 합 약 3~6만이다.
