# 실험 25 — J 상한 고르기 대안: 새 계정에서 「최선과 J ≤ 0.3」 대안이 후처리 뒤에도 97%를 넘는가

> 실험 24는 탐색 기록만으로(후처리 전) J ≤ 0.3 대안이 계정 기록 12개 중 11개에서 최선의 97% 이상임을 보였다.
> **새 계정**에서, 실험 21과 같은 고정 절차와 **같은 후처리(큐브 · 컨트롤 고정점)**를 대안에도 붙이면 그대로인가?

**상태: 완료(2026-11-01) — 판단(사전 등록): 통과(6/8).** 계획 · 기준은 결과 전에 커밋했다(`fe101db`).
- **사용자 결정(2026-11-01): 이 대안 「최선과 J ≤ 0.3 · 97% 이상」을 유력 대안의 공식 정의로 삼는다**([로드맵](../../docs/ROADMAP.md) 1단계). 실험 21 6번의 옛 정의(주력 딜러 배분)는 기록으로 둔다.
- 출처: 2026-11-01 사용자 결정 「(다)로 진행」. 실험 24 결정 후보 (가)다. (나)는 [실험 26](../26_alt_local/README.md)이다.
- 사용자 지시: 주력 딜러 개념은 쓰지 않는다.

## 왜 이것인가

- 실험 21의 유력 대안은 「최선 덱 두 개를 다시 짜고 그 두 덱의 주력을 주력에서 뺀 안」이었다. 실험 23으로 재 보니 최선과 J 0.27~0.54(중앙 0.42)였다.
- 실험 24에서 고르는 기준을 「J ≤ θ」로 바꾸면 θ = 0.3까지는 값이 거의 떨어지지 않았다. 다만 후처리 전 값이고 개발 계정이었다.
- 이번에는 후처리를 붙이고, 개발에 쓰지 않은 새 계정에서 잰다.

[실험 21 §조건](../21_first_goal_recheck/README.md)과 같다.

- 보스: 기본 적(허수아비)
- 운용: `accumulate`, 기대값, `solo`
- 풀: SSR 177명

### 평가 계정 — w1~w8 (결과 전 고정)

- 실험 21 u1~u8과 **같은 8가지 계정 모양**(미보유 강한 니케 · 육성 무작위 · 장탄 무작위 · 큐브 결손 · 렐릭 베어 없음 3 · 낮음 1)이다.
- **시드만 20261104로 바꿨다.** 그래서 미보유 니케 · 등급 · 장탄 · 큐브 레벨이 모두 다르다.
- 어느 실험의 개발 · 검증에도 쓰지 않은 계정이다.

## 절차

[`run25.py`](run25.py).

1. **최선 = 실험 21 P 판 그대로.**
   - 공유 사전 계산 U4를 옮겨 계정 탐색 3,000평가(`run10.run_method` P)
   - 5덱 고정점 후처리(JT 400, `run20.policy_pf`)
2. **대안(θ):**
   - 같은 계정 기록에서 고른다. 조건은 **후처리 뒤 최선 5덱과 쌍 자카드 J ≤ θ**이고, 그런 5덱 중 값 합이 가장 큰 것이다.
   - 값은 max(기본 레이어, 운용 값)이다.
   - 같은 고정점 후처리를 「J 상한 묶기」로 돈다(`policy_pf(packer = J 상한 묶기)`). 실험 21 유력 대안과 묶기 규칙만 다르다.
   - J 상한 묶기는 `run9.pack_vals(cost = 최선과의 공유 쌍, budget = ⌊100θ / (1 + θ)⌋)`다(실험 24에서 더한 선택 인자).
   - 제한 시간 300초를 넘으면 찾은 해를 쓰고 표시한다.
3. **θ = 0.3이 판정, θ = 0.2는 관찰이다.**

## 판단 기준 (사전 등록 — 결과 전)

| 판단 | 조건(θ = 0.3) |
|---|---|
| **통과** | 대안 5덱 합(후처리 뒤)이 최선 5덱 합(후처리 뒤)의 97% 이상인 계정이 **8개 중 6개 이상** |
| **미통과** | 그 밖 |

- 97% · 6/8은 실험 21 6번(유력 대안) 기준과 같은 문턱이다. 다른 정도의 조건만 「주력 딜러 배분 · 다시 짠 덱 2개」에서 「J ≤ 0.3」으로 바꿨다.
- J ≤ 0.3은 만드는 방식상 늘 맞는다.
- **통과해도 유력 대안의 공식 정의(1차 목표 기준 6번 · 로드맵)를 바꾸는 것은 사용자가 정한다.** 이 실험은 그 근거를 만든다.
- **관찰(판정에 안 씀):**
  - θ = 0.2 대안의 값 비율
  - 대안의 J · 바꿀 · 니케 공유
  - 대안 후처리 중 최선보다 높은 5덱이 나왔는지(`best_after_alt`)
  - 비용(최선 · 대안별 새 시뮬)
  - 실험 21 유력 대안의 J(0.27~0.54)와의 비교

## 예산과 실행

- 새 시뮬 예상: 계정마다 계정 탐색 약 3,000, 최선 후처리 약 2,000, 대안 후처리 θ마다 약 800~1,600. 8개 합 약 5~6만, 4프로세스로 약 1시간이다.

**관찰:**

1. **실험 21 유력 대안보다 묶음이 더 많이 바뀐다.**
   - θ = 0.3 대안: J 중앙 0.28, 바꿀 8~10명
   - 실험 21 유력 대안(실험 23 측정): J 중앙 0.42, 바꿀 5~10명(중앙 6)
   - 니케 공유는 21~24명으로 비슷하다. 같은 니케를 더 다르게 나눈다.
2. **문턱에 딱 걸렸다.** 6/8은 기준의 최소다. w3 · w5가 96.6%로 1%p 안쪽에서 빠졌다.
   - w3은 육성 · 장탄 · 큐브 레벨 무작위, w5는 강한 니케 5명 육성 하다.
3. **θ = 0.2는 후처리를 붙여도 개발 계정(실험 24)과 같은 모양이다.** 중앙 96.3%, 97% 이상 2/8이다.
   [실험 26](../26_alt_local/README.md#결과-2026-11-01)에서 대안 근처를 1,000평가 더 탐색하면 이 차이가 메워졌다(개발 계정, 후처리 전).
4. **대안을 후처리하다 최선보다 높은 5덱을 찾은 계정이 있다.**
   - w2: 대안이 최선의 101.5%, 그 과정의 기록으로 다시 짠 최선 +1.48%
   - w8: +0.32%
   - 실험 20 · 21에서도 본 「최선의 덱만 후처리하는 지금 절차가 놓치는 몫」이다.
   - 판정에는 P 판의 최선을 그대로 썼다(실험 21과 같은 방식).
5. **비용:** 대안 후처리는 계정당 1,600 안팎이다(θ = 0.3, w2만 2,000). 실험 21 유력 대안(800~1,600)과 비슷하거나 조금 많다.

**해석:** 「최선과 J ≤ 0.3 · 97% 이상」 대안은 새 계정 8개 중 6개에서 나왔다. 사전 등록 기준은 통과했지만 문턱에 걸렸다.
유력 대안의 공식 정의(1차 목표 기준 6번 · 로드맵)를 이것으로 바꿀지는 사용자가 정한다.
→ **사용자 결정(2026-11-01): 바꾼다.** 문턱에 걸린 통과라는 점을 알고 정했다.
