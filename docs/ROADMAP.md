목표와 네 단계의 정의는 [GOALS.md](GOALS.md), 탐색 방식과 성공 기준은 [SEARCH.md](SEARCH.md)가 정본이다.

## 로드맵

2026-10-11에 목적을 네 단계와 두 차수로 명확히 했다. **1차는 허수아비 보스에서 1~3단계까지,
2차는 임의 보스에 대한 4단계**다. 아래의 구현·검증 상태는 기존 사전 실험의 완료와 구분한다.

| 항목 | 현황 | 다음에 필요한 것 |
|---|---|---|
| 공통 기반 | **연결됨**: Rust 평가기(`nikke-sim`, 있으면 우선)·Python 평가기, 180초 평가, 캐시, 예산 관리, 인라인 육성, 운용 설정 전달. 버스트 게이지 실누적(`accumulate`)이 기본(2026-10-29) | 각 단계의 필요 조건과 평가기의 지원 범위 확인 |
| 방법 비교 연구 | 기존 국소 탐색·릿지 기반 사전 실험은 있음. 여러 기법·정보 활용·혼합 전략의 체계적 비교는 **미검증** | 공통 평가 문제와 기록 형식을 정하고 후보별 비교·구성 요소 비교를 반복 |
| **1. 계정별 조합 군집** | **최고 5덱 + 유력 대안 1개: 검증 기준 충족([실험 21](../experiments/21_first_goal_recheck/README.md#결과-2026-11-01) · 유력 대안은 [실험 25](../experiments/25_jpick_alt/README.md#결과-2026-11-01), 허수아비 · 측정 범위 안)**. 유력 대안 = **최선 5덱과 쌍 자카드 J ≤ 0.3이고 합이 최선의 97% 이상인 5덱**(2026-11-01 사용자 결정, [실험 25](../experiments/25_jpick_alt/README.md#결과-2026-11-01) 근거 — 새 계정 w1~w8 중 6/8, 문턱과 같은 통과). 고르는 법: 계정 기록에서 J ≤ 0.3인 5덱 중 합이 가장 큰 것을 고르고 J 상한 묶기로 같은 후처리(`run25`). 이전 정의(주력 딜러 배분이 다른 안 · 다시 짠 덱 2개 이상 · 97% 이상, [실험 20](../experiments/20_search_robust/README.md#결과-2026-11-01) · 21 — 새 계정 8개 모두, J 중앙 0.42)는 기록으로 둔다. 여러 군집의 후보군 · 탐색 중 군집 유지는 **미구현** | 실험 9: 다중 출발 · 대리 모델 선별(틀 재구성 포함)이 예산 800 이상에서 국소 탐색과 같음, 작은 예산은 랭커 30명만 옮기기. 실험 10: 랭커 없는 출발은 공유 사전 계산 옮기기(P)가 랭커 출발에 못지않음 — 단 랭커가 거른 60명 풀에서만. 5덱 킥은 효과 없음. 실험 11: SSR 177명 풀에서 사전 계산 예산을 15,000으로 키운 PB15가 K177(랭커 30명 + 177명)에 못지않음(800 +1.1% · 2,000 +0.8%) → 랭커 없는 기본 = PB15 + SSR 전부. 랭커 없이 풀 좁히기(PN · PM)는 돕지 않음. 실험 12: PB15는 시드 4개 중 3개에서 K177에 못지않음 — 뼈대를 못 찾은 시드 하나는 일부 계정에서 3~7% 짐. PBD · PBS는 우열 미확인 · 효과 없음. 실험 13 · 14: 시드 기록 합치기 — 시드 2개는 부족(새 쌍 1/2), 시드 4개 합치기는 두 번 모두 K177에 못지않음 → 랭커 없는 기본. 실험 15: 신캐 추가 뒤 갱신 — 짝 의존 신캐는 처음부터 다시, 단독 강자 · 대규모는 새 시드 하나 이어 붙이기로 충분, 갱신 없음은 불가. 실험 19: 미관측 계정 8개 중 6개에서 계정 탐색 2,000과 4,000이 같은 5덱, t5(렐릭 베어 없음)에서 덱 3개 재배분을 놓침(−2.5%). 대안 5덱은 최선과 21~25명 공유 — 뼈대가 다른 후보군 미해결. 실험 20 · 21: 계정 탐색 3,000으로 늘림(개발 t5의 늦은 재배분을 잡음, 새 계정에서는 차이 없음 · u8 −1.5%는 순서 다듬기 시점 차이), 유력 대안은 옛 정의로 해결. 실험 23 · 24 · 25: 유사도 J로 재고 「J ≤ 0.3 · 97%」로 정의를 바꿈(위) |
| **2. 조합 + 큐브** | **검증 기준 충족([실험 21](../experiments/21_first_goal_recheck/README.md#결과-2026-11-01), 허수아비 · 측정 범위 안)** — 실험 19(기준 3 미충족) → 실험 20 보강 → 실험 21. 장착 인원 제한 없음(사용자 2026-10-31) → 큐브는 니케마다 고르는 운용 축. 선택지 = 평가기 큐브 표에서 자동으로 뽑은 계정 보유 큐브(새 큐브는 다시 뽑으면 들어감). 실험 17 [결과](../experiments/17_cube_control/README.md#결과-2026-10-31): 컨트롤과 함께 찾으면 구성마다 중앙 +0.66%(컨트롤만 대비), 같은 400평가에서 **JT(니케별 사전값 상위 3 큐브 + 컨트롤) · 400**이 가장 좋음, 큐브를 함께 찾으면 컨트롤도 84%에서 바뀜 | 실험 19: 큐브 결손 · 저레벨 계정에서 운용 이득 중앙 +3.4%, 새 큐브(사전값 관찰 없음) 통과. 렐릭 베어 없는 계정(t5)에서 계정 탐색이 덱 3개 재배분을 놓쳤다 → 실험 20 · 21: 렐릭 베어 없음 · 낮음 계정도 기준 안(개발 5개 · 새 계정 4개) |
| **3. 조합 + 큐브 + 컨트롤** | **검증 기준 충족([실험 21](../experiments/21_first_goal_recheck/README.md#결과-2026-11-01), 허수아비 · 측정 범위 안)** — 실험 19(기준 3 미충족) → 실험 20 보강 → 실험 21. 실행 가능한 운용 범위는 정함(아래 1차 기준). 고정 조합의 컨트롤 탐색: 실험 6 [실행](../experiments/06_control_menu/README.md#결과)(좌표 하강은 국소 최선) → 실험 7 [검증](../experiments/07_control_search/README.md#결과): 반복 국소 탐색 M3:k2가 조합당 200평가에 상한 참조의 99.5%(중앙). 조합과 묶는 방법: 실험 8 [결과](../experiments/08_control_postproc/README.md#결과) — 후보 348개에서 기본 레이어 순 상위 10개에만 컨트롤을 찾아도 공동 탐색 상위 10 중 9개(20개면 10개), 비용은 공동 탐색의 3~6% → **컨트롤은 후처리**. 니케별 장전컨 기본값은 1차 순위를 바꾸지 않음; 실험 16: 기본 레이어 탐색이 컨트롤 의존 조합을 크게 놓치지 않음(L 중앙 +0.24%). 실험 18 [결과](../experiments/18_deck_post/README.md#결과-2026-10-31): **후처리 대상 = 5덱 고정점(5덱을 짜고 그 덱에 운용 탐색 → 다시 짜기)**, 운용 = JT 400 → 이전 기본(틀별 상위 5 + 컨트롤만) 대비 5덱 합 중앙 +1.93%(8개 모두 +1.3~2.8%), 비용 3,000 → 2,000평가 | 실험 21(새 계정 8개): 이전 기본 대비 중앙 +2.41%(같은 비용), 조합 탐색에만 쓰는 판 대비 +3.48%, 큰 예산 참조 대비 최소 98.50%. 남은 것: 실전 비교, 보스 패턴(4단계) |
| **4. 임의의 보스 패턴에 대응** | 보스 조건 입력 기반은 있음. 미관측 시간 패턴에서의 탐색은 **미검증** | 패턴 표현·평가기 지원 확인, 새 패턴에서 재탐색, 평가에 남겨 둔 보스에서 검증 |
| 지속 적용 조건 — 캐릭터 추가 후 갱신 | 갱신 절차·전체 소요 시간과 갱신 후 계정별 탐색 품질은 **미검증**. 모사만: 실험 15(갱신 규칙), 실험 19(미관측 계정에서 혼자 강한 신캐 뒤 I1이 F4와 중앙 −0.10%, 새 큐브는 사전값 없이 +0.00%) | 본 목표의 기법 비교에 갱신 비용·시간을 포함하고 캐릭터 추가를 모사해 검증 |

**1차는 허수아비에서 사전 등록한 검증 기준을 충족했다(실험 21, 측정 범위 안 — 실전 정확도 · 여러 군집의 후보군은 미검증). 2차는 미완료다.** 네 단계에 걸쳐 벤치마크와 예산별 성능·다양성 측정을 함께 개발한다.
**계정별 조합 최적화와 두 차수의 문제 해결이 우선**이며, 주기적 갱신은 기법의 지속 적용 조건으로 함께 확인한다.
갱신 속도 개선을 별도 선행 과제로 삼아 기존 공동 탐색 연구를 미루지 않는다.
신캐 추가와 계정·자원·조작 조건 변화는 1차부터 검증하며, 새 시간 패턴 대응은 2차로 확장한다.
시즌 사전 계산·대리 모델은 이 목표를 돕는 수단으로 선택하고, 부산물인 티어는 후순위로 둔다.

### 우선 진행할 검증

1. **1차 기준 마련 — 일부 결정.** 180초 허수아비의 정적 조건, 시험할 계정·자원·실행 가능한 컨트롤 범위,
   신캐 추가 시험과 기준선을 정한다. 기존 S40 실험은 참고 자료이며 허수아비 공동 최적화의 검증을 대신하지 않는다.
   - 결정(2026-10-29): 버스트 게이지는 `accumulate`. 실행 가능한 컨트롤은 한 번에 한 명 수동 조작(돌아가며 조작 가능)과
     버스트 순서·타이밍 조작 — 평가기 `solo` 모드와 버스트 축으로 표현한다. 큐브 공동 탐색이 작업을 크게 늘리면
     렐릭 베어 큐브(재장전 속도, 기본 스펙 큐브)로 고정한다.
   - 임시: 타깃은 평가기 기본 적(패턴·속성·코어·파츠 없음, 방어력 31784). 계정·신캐 시험과 기준선은 실험 19가 처음 정했다
     (미관측 계정 t1~t8, 판 B0 고정 운용 · B1 이전 기본 · B0w 조합 탐색 4,000 · REF 큰 예산 참조, 문턱 임시).
2. **1~3단계 공동 탐색과 효율 검증 — 검증 기준 충족(허수아비 · 측정 범위 안).** 실험 19(기준 3 미충족) → 실험 20(계정 탐색 3,000 · 유력 대안 기준 다듬기) → 실험 21(새 계정 8개, 기준 1 · 2 · 3 · 6 충족) → 실험 25(유력 대안 새 정의 J ≤ 0.3 · 97%, 새 계정 w1~w8 중 6/8). 같은 시뮬 예산에서의 최고해와 유력 대안,
   같은 해 품질에 도달하는 횟수를 측정한다. 사전 계산과 새 문제의 준비·탐색 비용을 구분하고,
   개발에서 보지 않은 상황에 알고리즘·갱신 절차를 고정해 적용한다. 캐릭터 추가 후 필요한 갱신을 허용하고,
   그 전체 시간·계산 비용과 갱신 후 계정별 탐색 품질을 함께 확인한다. 구체적 수치 기준은 실험 전에 정한다.
3. **2차 확장 — 미완료.** 보스 시간 패턴·평가기 지원·캐시 식별을 확인하고, 1차의 탐색·측정 절차를
   미관측 패턴 적응으로 확장한다. 당해 보스 랭커 정답 없이도 품질과 시뮬 효율을 검증한다.

알고리즘 개발 기간의 단축보다 이후 새 문제를 적은 시뮬로 푸는 능력을 우선한다. 계정별 탐색 응답 시간의 상한은 미정이다.
주기적 갱신에는 [목표 명세의 운영 조건](GOALS.md#반복해서-새-문제를-푸는-능력)을 적용하며, 구체적인 시간 상한은 아직 미정이다.
비용 집계·도달 품질·평가 자료 분리는 [탐색 설계](SEARCH.md)를 따른다.

### 방법 비교 연구의 다음 작업

진행 방식은 [연구 회차](SEARCH.md#연구-회차-계획--실험--해석--다음-방향-결정)를 따른다.
아래 질문·기법은 후보로 유지하고, 실행 순서와 한 기법을 더 연구할지는 회차 결과로 갱신한다.

- **현재 상태(2026-11-01, 큐브 세션 끝):** **1차 목표 검증 기준 충족(허수아비 · 측정 범위 안)** — [실험 21](../experiments/21_first_goal_recheck/README.md#결과-2026-11-01). 개발에 쓰지 않은 새 계정 u1~u8(렐릭 베어 없음 3 · 낮음 1 포함)에 고정 절차를 적용했다.
  - 고정 절차: 공유 사전 계산 U4 → 계정 탐색 U4 · 3,000 → 5덱 고정점 후처리 · 큐브 + 컨트롤 JT 400.
  - 이전 기본(틀별 상위 5 · 컨트롤만) 대비 5덱 합 중앙 +2.41%(같은 비용), 같은 쪽 예산을 조합 탐색에만 쓰는 판 대비 +3.48%, 큰 예산 참조 대비 최소 98.50%.
  - 유력 대안(옛 정의 — 주력 딜러 배분이 다른 안)은 8개 모두 최선의 97.5 ~ 99.0%였다. 공식 정의는 이후 「최선과 J ≤ 0.3 · 97% 이상」으로 바뀌었다(실험 25, 아래).
  - 거쳐 온 길: [실험 19](../experiments/19_first_goal/README.md#결과-2026-11-01)(기준 3 미충족 — 렐릭 베어 없는 t5에서 덱 3개 재배분 누락) → [실험 20](../experiments/20_search_robust/README.md#결과-2026-11-01)(계정 탐색 3,000 · 유력 대안 기준 다듬기).
  - 같은 날 5덱 묶기 속도 개선(결과 같음) · 평가 캐시 잠금 수정이 있었다. 새 시뮬은 실험 19 88,951 · 실험 20 74,821 · 실험 21 72,462회다.

## 기존 사전 실험의 조건과 적용 범위

- **육성**: 실험 2–4는 전원 기본 스펙, 실험 5는 가상의 결손·육성 등급 8개 시나리오다. 임의의 실제 계정 전반은 미검증이다.
- **보스·운용**: 실험 2–5는 S40와 정해진 큐브·컨트롤 조건이다. 당시 확인한 레이드 프리셋은 S40 하나였다.
  버스트 게이지는 지정하지 않아 평가기 기본 `fixed`(캐릭터별 표 값으로 사이클 고정)였다 — 실제 게이지 충전 차이와
  버충·카메라 컨트롤이 반영되지 않은 순위다. 이후 실험은 `accumulate`를 쓴다.
  보스 파라미터 입력 기능이 있어도 미관측 시간 패턴에 대한 적응 성능이 검증된 것은 아니다.
- **검증한 목표**: 기존 결과는 단일 최고 편성의 시뮬 성능을 다룬다. 유력 군집 발견, 큐브·컨트롤 공동 탐색, 임의 패턴 대응은 미검증이다.
- **주기적 갱신**: 기존 실험은 캐릭터 추가 후 갱신 절차의 비용·시간이나 갱신 후 계정별 탐색 품질을 검증하지 않았다.

## 사전 실험 (본격 구현 전에 "풀 만한가"를 확인)

1. **경향 안정성** — 랭커 데이터만으로, 시즌(보스)이 바뀔 때 사용률 순위·자주 붙는 짝이 얼마나
   유지되는지 잰다. 사전 지식을 얼마나 믿을지 정한다.
   **→ 완료** ([결과](../experiments/01_trend_stability/README.md)): 니케 단위는 잘 맞고(과거 기반 상위 50명이
   이번 주력 25명의 90%, 나머지는 주로 신캐), 과거 스쿼드 ±1명이 덱의 76%를 덮는다. 짝은 보스마다 크게 바뀐다.
2. **점수 분포** — 한 보스·한 로스터에서 구조 규칙을 통과한 무작위 스쿼드 1~2천 개를 180초로 돌려
   딜 분포를 본다. 상위권이 얼마나 뾰족한지, 유효 후보가 얼마나 되는지.
   **→ 완료** ([결과](../experiments/02_score_distribution/README.md), S40·풀 60명·기본 스펙·시뮬 1,849회):
   유효 후보가 극히 드물다 — 무작위 1,500개의 최고가 랭커 구성 1위의 62%이고, 랭커 구성 중앙값이 무작위 99백분위다.
   이 조건에서는 균등 탐색보다 사전 지식이 유리했다. 배치 순서는 한 구성 안에서 중앙 19%(최대 2배)를 바꾸지만
   구성 순위는 거의 그대로였다(Spearman 0.97). 상위 구성만 순서를 다듬는 기준선의 근거이며, 큐브·컨트롤 후처리의 근거는 아니다.
3. **학습 가능성** — 2의 데이터로 "니케 단위 + 짝" 단순 모델이 처음 보는 조합의 순위를 맞히는지
   (순위 상관) 본다. 대리 모델이 필요한지, 가지치기 + 전수 탐색으로 충분한지 가른다.
   **→ 완료** ([결과](../experiments/02_score_distribution/README.md#결과--실험-3-학습-가능성)): 「니케 + 짝」 릿지가
   교차검증 Spearman 0.86, 분포 밖(랭커 구성)에서도 0.79. 400개면 0.83. 상위 10% 안의 순위는 0.6이라 최종 판정은 시뮬로.
   짝을 타는 핵심 니케(솔린 : 프로스트 티켓·토브·프리카)는 단독 평균으로 보면 오히려 손해라 짝 항이 필요하다.
4. **개선 여지** — 큰 예산으로 찾은 최선 5덱 vs 랭커 구성 기준선. 시뮬 성능 개선을 재는 실험이다.
   랭커 빈출 스쿼드가 이번 보스 시뮬에서도 상위권인지도 함께 보아 사전 지식의 쓸모를 잰다.
   **→ 1차 완료** ([결과](../experiments/04_improvement_margin/README.md), 평가 801회): 이 조건과 탐색에서는
   랭커 1위 5덱 309.3억 → 탐색 310.9억(+0.5%). 다른 뼈대의 최적성은 확인하지 않았다. 상위 스쿼드 근처만 파면 1덱만 강해지고 다른 덱과
   겹쳐 합이 그대로였고, **5덱을 함께 고치는 수**(다른 덱이 안 쓰는 니케 교체·덱 간 맞교환)만 합을 올렸다.
   전원 보유·같은 육성이라는 랭커에 유리한 조건이다. → 결손 계정은 실험 5.
5. **로스터 결손** — 핵심 니케가 없거나 육성이 고르지 않은 계정에서 「랭커 구성 옮기기 + 대체」 대 탐색.
   **→ 완료** ([결과](../experiments/05_roster_deficit/README.md), 시나리오 8개 · 탐색 각 800회 · 시뮬 6,232회):
   결손이 있으면 탐색이 기준선(랭커 300명을 옮겨 시뮬로 고른 최고)을 **+1~11%** 넘는다 — 무작위 3명 미보유 +4%,
   6명 +6~10%, 육성 불균형 +11%. 아무 랭커나 따라 한 경우 대비 +3~19%. 랭커가 이미 풀어 둔 결손(레드 후드 하나 없음)은 +0.8%.
   탐색은 빈자리를 메우는 대신 남은 핵심 니케를 **다른 덱으로 옮기고** 빈 덱을 랭커가 안 쓰는 니케로 새로 짰다.
   육성이 낮은 핵심 니케도 짝이 맞는 자리에선 쓴다(같은 6명이 없을 때보다 +5%). 300회면 800회 개선의 대부분(중앙 85%)이고,
   여러 랭커의 옮긴 덱을 다시 조립만 해도 시뮬 0회 추가로 +0.4~2.9%다.
