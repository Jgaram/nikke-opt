# 로드맵과 실험 현황

목표와 네 단계의 정의는 [GOALS.md](GOALS.md), 탐색 방식과 성공 기준은 [SEARCH.md](SEARCH.md)가 정본이다.

## 로드맵

2026-10-11에 목적을 네 단계와 두 차수로 명확히 했다. **1차는 허수아비 보스에서 1~3단계까지,
2차는 임의 보스에 대한 4단계**다. 아래의 구현·검증 상태는 기존 사전 실험의 완료와 구분한다.

| 항목 | 현황 | 다음에 필요한 것 |
|---|---|---|
| 공통 기반 | **연결됨**: Rust 평가기(`nikke-sim`, 있으면 우선)·Python 평가기, 180초 평가, 캐시, 예산 관리, 인라인 육성, 운용 설정 전달. 버스트 게이지 실누적(`accumulate`)이 기본(2026-10-29) | 각 단계의 필요 조건과 평가기의 지원 범위 확인 |
| 방법 비교 연구 | 기존 국소 탐색·릿지 기반 사전 실험은 있음. 여러 기법·정보 활용·혼합 전략의 체계적 비교는 **미검증** | 공통 평가 문제와 기록 형식을 정하고 후보별 비교·구성 요소 비교를 반복 |
| **1. 계정별 조합 군집** | 계정별 단일 최고 편성의 국소 탐색은 실험됨. 군집 유지·다양한 대표안 반환은 **미구현·미검증** | 뼈대·성능 기준을 정하고 다중 출발·틀 재구성을 기존 탐색과 비교. 계정별 후보군과 5덱 조립을 연결 |
| **2. 조합 + 큐브** | 설정 전달만 가능. 공동 탐색은 **미구현·미검증** | 소유·레벨·장착 제약을 반영하고 고정 큐브·후처리 기준선과 같은 예산으로 비교 |
| **3. 조합 + 큐브 + 컨트롤** | 설정 전달만 가능. 공동 탐색은 **미구현·미검증**. 실행 가능한 운용 범위는 정함(아래 1차 기준). 니케별 컨트롤 선택지 실험 [계획](../experiments/06_control_menu/README.md) | 실험 6으로 컨트롤을 고정 조건·후처리·공동 탐색 중 어떻게 다룰지 정하고, 운용에 따라 살아나는 조합의 발견과 민감도를 검증 |
| **4. 임의의 보스 패턴에 대응** | 보스 조건 입력 기반은 있음. 미관측 시간 패턴에서의 탐색은 **미검증** | 패턴 표현·평가기 지원 확인, 새 패턴에서 재탐색, 평가에 남겨 둔 보스에서 검증 |
| 지속 적용 조건 — 캐릭터 추가 후 갱신 | 갱신 절차·전체 소요 시간과 갱신 후 계정별 탐색 품질은 **미검증** | 본 목표의 기법 비교에 갱신 비용·시간을 포함하고 캐릭터 추가를 모사해 검증 |

**두 차수 모두 아직 완료하지 않았다.** 네 단계에 걸쳐 벤치마크와 예산별 성능·다양성 측정을 함께 개발한다.
**계정별 조합 최적화와 두 차수의 문제 해결이 우선**이며, 주기적 갱신은 기법의 지속 적용 조건으로 함께 확인한다.
갱신 속도 개선을 별도 선행 과제로 삼아 기존 공동 탐색 연구를 미루지 않는다.
신캐 추가와 계정·자원·조작 조건 변화는 1차부터 검증하며, 새 시간 패턴 대응은 2차로 확장한다.
시즌 사전 계산·대리 모델은 이 목표를 돕는 수단으로 선택하고, 부산물인 티어는 후순위로 둔다.

### 우선 진행할 검증

1. **1차 기준 마련 — 일부 결정.** 180초 허수아비의 정적 조건, 시험할 계정·자원·실행 가능한 컨트롤 범위,
   신캐 추가 시험과 기준선을 정한다. 기존 S40 실험은 참고 자료이며 허수아비 공동 최적화의 검증을 대신하지 않는다.
   - 결정(2026-10-29): 버스트 게이지는 `accumulate`. 실행 가능한 컨트롤은 한 번에 한 명 수동 조작(돌아가며 조작 가능)과
     버스트 순서·타이밍 조작 — 평가기 `solo` 모드와 버스트 축으로 표현한다. 큐브 공동 탐색이 작업을 크게 늘리면
     렐릭 베어 큐브(재장전 속도, 기본 스펙 큐브)로 고정한다.
   - 임시: 타깃은 평가기 기본 적(패턴·속성·코어·파츠 없음, 방어력 31784). 계정·신캐 시험과 기준선은 미정이다.
2. **1~3단계 공동 탐색과 효율 검증 — 미구현·미검증.** 같은 시뮬 예산에서의 최고해와 유력 대안,
   같은 해 품질에 도달하는 횟수를 측정한다. 사전 계산과 새 문제의 준비·탐색 비용을 구분하고,
   개발에서 보지 않은 상황에 알고리즘·갱신 절차를 고정해 적용한다. 캐릭터 추가 후 필요한 갱신을 허용하고,
   그 전체 시간·계산 비용과 갱신 후 계정별 탐색 품질을 함께 확인한다. 구체적 수치 기준은 실험 전에 정한다.
3. **2차 확장 — 미완료.** 보스 시간 패턴·평가기 지원·캐시 식별을 확인하고, 1차의 탐색·측정 절차를
   미관측 패턴 적응으로 확장한다. 당해 보스 랭커 정답 없이도 품질과 시뮬 효율을 검증한다.

알고리즘 개발 기간의 단축보다 이후 새 문제를 적은 시뮬로 푸는 능력을 우선한다. 계정별 탐색 응답 시간의 상한은 미정이다.
주기적 갱신에는 [목표 명세의 운영 조건](GOALS.md#반복해서-새-문제를-푸는-능력)을 적용하며, 구체적인 시간 상한은 아직 미정이다.
비용 집계·도달 품질·평가 자료 분리는 [탐색 설계](SEARCH.md)를 따른다.

### 방법 비교 연구의 다음 작업

진행 방식은 [연구 회차](SEARCH.md#연구-회차-계획--실험--해석--다음-방향-결정)를 따른다.
아래 질문·기법은 후보로 유지하고, 실행 순서와 한 기법을 더 연구할지는 회차 결과로 갱신한다.

- **현재 상태:** 연구 회차 1을 계획했다 — [실험 6 니케별 컨트롤 선택지와 조합 의존성](../experiments/06_control_menu/README.md) (미실행).
  컨트롤 오토 고정 + 조합 탐색(A), 조합 고정 + 원자 단위 컨트롤(B), 조합 고정 + 특징적 컨트롤 선택지(C)를 검토했다.
  완전 오토도 평가기 기본 레이어도 임의적인 고정 조건이라, 조합 연구 전에 C로 컨트롤의 조합 의존성과 탐색 비용부터 잰다.
  A의 완전 오토는 비교 조건으로 두고, B는 선택지로 표현되지 않는 운용이 의심될 때 상한 확인용으로 보류했다.
- **다음 행동:** 실험 6의 준비 작업(Rust ↔ 원본 대조, 선택지 생성, 조합 선정)을 한 뒤 실행한다.
  결과에 따라 기본 레이어 고정 · 데이터 기본 레이어 · 공동 탐색 중 다음 방향을 정하고 이 항목을 갱신한다.
- **검토할 질문:** 총딜만 활용할 때와 실행 전 특성·평가 후 세부 피드백을 추가할 때의 효과,
  탐색 기법 자체의 효과, 방법 간 결합·상황별 선택·예산 배분의 효과. 필요한 평가기 출력과 평가 조건을 확인해
  현재 질문을 시험할 준비가 된 후보부터 연구한다. 모든 질문을 미리 정한 순서로 소진하는 일정은 두지 않는다.

- 랭커를 적게 옮기고 새 뼈대 탐색에 예산을 더 쓰는 편이 유리한가? 실험 5는 많은 랭커를 평가한 뒤 출발했으므로
  작은 총예산에서의 배분은 미확인이다. [후속 메모](../experiments/05_roster_deficit/README.md#후속-검토-메모)에 기존 관찰을 보존했다.

- 군집 유지와 대리 모델이 같은 예산에서 실제로 도움 되는가? 현재 실험의 예측 이득 탐욕 선택과 임의 예산 배분을 기준선으로 두고,

- 고정 운용의 조합 선별이 큐브·컨트롤과의 상호작용 때문에 어떤 후보를 누락하는가? 배치 순서 실험 결과를 대신 근거로 쓰지 않는다.
  컨트롤 쪽은 [실험 6](../experiments/06_control_menu/README.md)이 먼저 잰다.
- 캐릭터 추가 후 같은 절차로 갱신하고 계정별 유력 편성을 계속 찾을 수 있는가? 허수아비에서부터 자원 재배분과
  해 품질·시뮬 효율을 검증하고, 갱신 전체의 시간·계산 비용과 계정별 탐색 비용을 구분한다.
- 당해 보스 랭커 데이터 없이 새 패턴에서 어느 정도 적응하는가? 기존 S40 실험과 분리해서 검증한다.

## 기존 사전 실험의 조건과 적용 범위

- **육성**: 실험 2–4는 전원 기본 스펙, 실험 5는 가상의 결손·육성 등급 8개 시나리오다. 임의의 실제 계정 전반은 미검증이다.
- **보스·운용**: 실험 2–5는 S40와 정해진 큐브·컨트롤 조건이다. 당시 확인한 레이드 프리셋은 S40 하나였다.
  버스트 게이지는 지정하지 않아 평가기 기본 `fixed`(캐릭터별 표 값으로 사이클 고정)였다 — 실제 게이지 충전 차이와
  버충·카메라 컨트롤이 반영되지 않은 순위다. 이후 실험은 `accumulate`를 쓴다.
  보스 파라미터 입력 기능이 있어도 미관측 시간 패턴에 대한 적응 성능이 검증된 것은 아니다.
- **검증한 목표**: 기존 결과는 단일 최고 편성의 시뮬 성능을 다룬다. 유력 군집 발견, 큐브·컨트롤 공동 탐색, 임의 패턴 대응은 미검증이다.
- **주기적 갱신**: 기존 실험은 캐릭터 추가 후 갱신 절차의 비용·시간이나 갱신 후 계정별 탐색 품질을 검증하지 않았다.

## 사전 실험 (본격 구현 전에 "풀 만한가"를 확인)

1. **경향 안정성** — 랭커 데이터만으로, 시즌(보스)이 바뀔 때 사용률 순위·자주 붙는 짝이 얼마나
   유지되는지 잰다. 사전 지식을 얼마나 믿을지 정한다.
   **→ 완료** ([결과](../experiments/01_trend_stability/README.md)): 니케 단위는 잘 맞고(과거 기반 상위 50명이
   이번 주력 25명의 90%, 나머지는 주로 신캐), 과거 스쿼드 ±1명이 덱의 76%를 덮는다. 짝은 보스마다 크게 바뀐다.
2. **점수 분포** — 한 보스·한 로스터에서 구조 규칙을 통과한 무작위 스쿼드 1~2천 개를 180초로 돌려
   딜 분포를 본다. 상위권이 얼마나 뾰족한지, 유효 후보가 얼마나 되는지.
   **→ 완료** ([결과](../experiments/02_score_distribution/README.md), S40·풀 60명·기본 스펙·시뮬 1,849회):
   유효 후보가 극히 드물다 — 무작위 1,500개의 최고가 랭커 구성 1위의 62%이고, 랭커 구성 중앙값이 무작위 99백분위다.
   이 조건에서는 균등 탐색보다 사전 지식이 유리했다. 배치 순서는 한 구성 안에서 중앙 19%(최대 2배)를 바꾸지만
   구성 순위는 거의 그대로였다(Spearman 0.97). 상위 구성만 순서를 다듬는 기준선의 근거이며, 큐브·컨트롤 후처리의 근거는 아니다.
3. **학습 가능성** — 2의 데이터로 "니케 단위 + 짝" 단순 모델이 처음 보는 조합의 순위를 맞히는지
   (순위 상관) 본다. 대리 모델이 필요한지, 가지치기 + 전수 탐색으로 충분한지 가른다.
   **→ 완료** ([결과](../experiments/02_score_distribution/README.md#결과--실험-3-학습-가능성)): 「니케 + 짝」 릿지가
   교차검증 Spearman 0.86, 분포 밖(랭커 구성)에서도 0.79. 400개면 0.83. 상위 10% 안의 순위는 0.6이라 최종 판정은 시뮬로.
   짝을 타는 핵심 니케(솔린 : 프로스트 티켓·토브·프리카)는 단독 평균으로 보면 오히려 손해라 짝 항이 필요하다.
4. **개선 여지** — 큰 예산으로 찾은 최선 5덱 vs 랭커 구성 기준선. 시뮬 성능 개선을 재는 실험이다.
   랭커 빈출 스쿼드가 이번 보스 시뮬에서도 상위권인지도 함께 보아 사전 지식의 쓸모를 잰다.
   **→ 1차 완료** ([결과](../experiments/04_improvement_margin/README.md), 평가 801회): 이 조건과 탐색에서는
   랭커 1위 5덱 309.3억 → 탐색 310.9억(+0.5%). 다른 뼈대의 최적성은 확인하지 않았다. 상위 스쿼드 근처만 파면 1덱만 강해지고 다른 덱과
   겹쳐 합이 그대로였고, **5덱을 함께 고치는 수**(다른 덱이 안 쓰는 니케 교체·덱 간 맞교환)만 합을 올렸다.
   전원 보유·같은 육성이라는 랭커에 유리한 조건이다. → 결손 계정은 실험 5.
5. **로스터 결손** — 핵심 니케가 없거나 육성이 고르지 않은 계정에서 「랭커 구성 옮기기 + 대체」 대 탐색.
   **→ 완료** ([결과](../experiments/05_roster_deficit/README.md), 시나리오 8개 · 탐색 각 800회 · 시뮬 6,232회):
   결손이 있으면 탐색이 기준선(랭커 300명을 옮겨 시뮬로 고른 최고)을 **+1~11%** 넘는다 — 무작위 3명 미보유 +4%,
   6명 +6~10%, 육성 불균형 +11%. 아무 랭커나 따라 한 경우 대비 +3~19%. 랭커가 이미 풀어 둔 결손(레드 후드 하나 없음)은 +0.8%.
   탐색은 빈자리를 메우는 대신 남은 핵심 니케를 **다른 덱으로 옮기고** 빈 덱을 랭커가 안 쓰는 니케로 새로 짰다.
   육성이 낮은 핵심 니케도 짝이 맞는 자리에선 쓴다(같은 6명이 없을 때보다 +5%). 300회면 800회 개선의 대부분(중앙 85%)이고,
   여러 랭커의 옮긴 덱을 다시 조립만 해도 시뮬 0회 추가로 +0.4~2.9%다.
