# 탐색 설계와 검증

[목표 명세](GOALS.md)를 구현하기 위한 설계 초안이다. [로드맵](ROADMAP.md)의 구현·검증 상태와 구분한다.

## 연구 원칙: 여러 방법을 비교하며 발전시킨다

특정 기법을 제품의 정답으로 먼저 정하지 않는다. **좋은 해를 적은 시뮬로 찾는다는 목표와 검증 기준을 유지하면서,
여러 접근을 구현·비교·수정하는 연구**를 진행한다. 대리 모델이나 사전 지식을 활용하는 접근도 검증할 후보이며,
최종 총딜만 피드백으로 받는 접근, 세부 전투 정보를 활용하는 접근, 둘을 결합하는 접근을 비교할 수 있다.

기법과 정보 활용은 별개 축이다. 총딜만 학습한다고 반드시 강화학습인 것은 아니며,
강화학습도 스킬 정보와 전투 기록을 관찰할 수 있다. 아래 예시는 연구 후보로, 전부 구현할 의무나 고정된 순서는 없다.

| 비교 축 | 후보 예시 |
|---|---|
| 탐색 방법 | 다중 출발 국소 탐색, 진화 탐색, 대리 모델 기반 순차 최적화·베이지안 최적화, 강화학습 |
| 실행 전 정보 | 조합·운용·계정·보스 입력, 버스트 단계·쿨타임·스킬 특성 추가, 과거 편성 지식 활용 |
| 실행 후 피드백 | 총딜만, 캐릭터별 딜·버스트·게이지·조작 기록 추가, 여러 결과를 함께 예측하는 학습 |
| 결합과 배분 | 후보 생성과 평가 선택에 서로 다른 방법 사용, 탐색 단계·상황·예산에 따른 방법 전환, 여러 탐색기에 예산 배분 |

- **작은 비교부터 반복한다.** [AI 분석 가이드](../AI_분석가이드.md)에 따라 기준선과 유력 후보 2~3개부터 시작한다.
  이는 초기 비교의 출발 규모이며 전체 연구의 기법 수 제한이 아니다. 이후 회차에서는 결과에 따라 한 기법을 깊게
  분석하거나 다른 기법과 비교한다. 매 회차 여러 기법을 한꺼번에 시험할 필요는 없다.
  복잡하거나 개발에 오래 걸린다는 이유만으로 후보를 영구 제외하지 않고, 필요한 데이터·환경과 검토 조건을 기록한다.
- **무엇이 효과를 냈는지 구분한다.** 정보 추가의 효과를 볼 때는 탐색 방법을 고정하고, 방법을 비교할 때는
  이용 가능한 정보를 맞춘다. 변경 요소를 하나씩 넣고 빼는 비교와 전체 방식의 비교를 구분하며, 이후 요소 간 상호작용도 확인한다.
  정보 사용 범위 자체가 비교 대상이면 그 차이를 명시한다. 모든 축의 곱집합을 처음부터 전수 시험할 필요는 없다.
- **여러 방법의 결합도 검증 대상이다.** 혼합 탐색은 모든 방법이 쓴 시뮬을 합산한 같은 총예산으로 단독 방법과 비교한다.
  방법 선택·전환·배분 규칙은 개발 자료에서 정하고 미관측 문제에서 검증한다. 각 문제의 정답을 본 뒤 가장 잘한 방법을
  고른 결과를 실제 선택기의 성능으로 보고하지 않는다. 단일 승자가 없으면 상황·예산별로 유리한 방법을 남긴다.
- **세부 피드백과 최종 목표를 구분한다.** 최종 비교는 180초 5덱 합산 딜과 유력 대안의 발견으로 한다.
  세부 지표는 후보 제안·예측·학습 보조에 쓸 수 있다. 보조 보상을 시험한다면 원래 총딜 목표에서의 효과를 별도로 검증한다.
  아직 실행하지 않은 후보의 실제 전투 기록은 미리 알 수 없으므로, 과거 기록과 새 후보의 예측값을 구분한다.

평가기·요청과 결과 기록·예산 집계·평가 문제를 공통 기반으로 두고, 후보 생성·평가 선택·학습·5덱 조립의
구현은 교체·조합할 수 있게 연구한다. 실험별 가설, 이용 정보, 고정·변경 요소, 준비·학습·탐색 비용,
채택·보류·실패 이유를 남긴다. 이 비교 체계와 각 후보의 실제 구현 상태는 로드맵에 별도로 기록한다.

### 연구 회차: 계획 → 실험 → 해석 → 다음 방향 결정

**장기 목표를 유지하며 단기 연구 계획을 결과에 따라 갱신한다.** 기법 목록은 검토할 후보군이고,
실제 연구 순서는 각 회차에서 얻은 근거로 정한다. 연구 계획에는 무엇을 시험할지와 함께
어떤 결과가 나오면 현재 기법을 더 파볼지, 수정할지, 다른 기법으로 넘어갈지의 판단 근거를 적는다.

1. **질문과 계획을 정한다.** 현재 병목·미확인 사항, 검증할 가설, 이 실험을 먼저 할 이유를 기록한다.
   기준선·고정 조건·바꿀 요소·평가 문제·시뮬 예산과 검토 시점을 정하고, 기대 효과와 심화·전환 판단 기준을 둔다.
   수치 기준의 근거가 부족하면 임시 기준임을 표시한다. 계획은 현재 질문을 판별할 수 있는 범위로 구체화한다.
2. **실험하고 기록한다.** 계획에 맞춰 실행하며 실제 평가 비용·결과·오류·예상 밖 관찰을 남긴다.
   도중에 조건이나 예산을 바꾸면 원래 계획과 변경 이유를 보존한다.
3. **결과를 해석한다.** 개선 폭뿐 아니라 어느 조건에서 효과가 났는지, 실패 원인과 남은 불확실성을 살핀다.
   구현 오류·평가기 미지원·정보 부족과 기법 자체의 한계를 구분한다. 관찰로 확인한 사실과 원인에 대한 가설도 나눈다.
4. **다음 방향을 결정한다.** 아래 판단 중 현재 근거에 맞는 것을 선택하고, 추가 연구로 얻을 정보·개선 가능성과
   필요한 비용을 비교한다. 이미 들인 노력만으로 같은 기법을 계속하거나 한 번의 부진만으로 폐기하지 않는다.
5. **후속 계획을 갱신한다.** 다음에 검증할 질문·변경점·예산·판단 기준을 구체화하고 로드맵의 현재 초점을 갱신한다.
   각 회차는 결과와 다음 행동의 근거까지 남겨 마무리한다.

| 판단 | 근거와 후속 행동 |
|---|---|
| **심화** | 재현되는 효과나 검증할 개선 가설이 있음. 어느 요소가 효과를 냈는지 분석하고 해당 기법의 표현·탐색·학습 등을 더 시험 |
| **수정 후 재검증** | 구현·입력 표현·평가 조건 등 구체적 문제가 확인됨. 이를 바로잡아 같은 가설을 다시 확인 |
| **추가 확인** | 표본·조건·시드에 따라 결론이 불분명함. 판단을 가를 실험을 정하고 그때까지 우열은 미확인으로 유지 |
| **전환·보류** | 공정한 비교에서 효과가 부족하고 다음 개선 가설의 근거가 약하거나, 다른 접근이 현재 병목을 더 잘 검증할 수 있음. 한계·재개 조건을 남기고 연구 초점을 이동 |
| **현재 범위에서 채택** | 정한 품질·비용 기준과 검증 범위를 충족함. 재현 가능한 기준선으로 보존하고 남은 조건·문제로 연구를 확장 |

회차별 계획·결과·판단은 해당 실험 문서에 연결하고, [로드맵](ROADMAP.md)에는 현재 질문·최근 판단·다음 실험과
기록 위치를 요약한다. 연구 결과로 계획을 바꾸는 과정은 개발에 해당한다. 최종 평가 자료를 보고 방향을 수정했다면
그 자료를 독립 검증으로 계속 사용하지 않는다. 사용자는 목적·게임 조건을 보완하고, AI는 기법 후보·실험 설계·결과 해석과
후속 방향을 근거와 함께 제안한다. 매번 사용자가 기법 이름이나 튜닝 값을 골라야 하는 방식으로 진행하지 않는다.

## 예산은 평가 횟수로 센다

탐색 예산의 단위는 **180초 시뮬레이션 횟수**다. 평가기 속도는 엔진 교체·병렬화·
포팅으로 얼마든지 바뀌지만(참고: 딜도로 제작자는 Rust 포팅을 속도 개선 방법으로 꼽는다), "몇 번 돌려서
얼마나 좋은 답을 찾았나"로 탐색 효율을 비교할 수 있다. 같은 평가기·버전·조건에서 비교하며,
엔진 교체로 딜이나 지원 기능이 달라지면 별도 검증한다. **현재 계정별 탐색 응답 시간의 상한은 정하지 않는다.**
추후 운영상 시간 제한이 필요하면 평가 비용과 병렬성을 측정해 횟수 예산을 정하되,
탐색 효율은 시뮬 횟수 대비 해 품질로 비교한다. 이 지표와 함께 주기적 갱신의 실제 시간·계산 비용으로
기법의 실용성을 확인한다. 평가기 엔진 자체의 속도 최적화는 당분간 이 레포의 관심사가 아니다.

| 예산 N (감각) | 의미 |
|---|---|
| ~10회 | 5덱 한 벌 검증이 5회. 사실상 **사전 지식이 답을 내는** 구간 |
| ~수백 회 | 사전 지식 + 국소 개선 |
| ~수천 회 이상 | **탐색이 주도하는** 구간 |

큐브·컨트롤·보스 조건을 바꿔 실제 시뮬을 추가하면 각각 예산을 쓴다. 작은 예산에서는 충분한 군집을 찾지 못할 수 있으므로
발견·검증한 범위를 보고한다. 벤치마크는 기준선 준비와 탐색에 든 비용, 사전 계산·캐시로 제공한 지식을 따로 기록하고
비교 방법에 같은 출발 정보와 예산을 준다.

### 개발·사전 준비·새 문제 탐색의 비용

오래 개발한 알고리즘이 이후 여러 문제를 적은 시뮬로 풀게 하는 것이 목적이다. 비용은 다음처럼 구분한다.

| 구분 | 기록할 것 |
|---|---|
| 알고리즘 개발·검증 | 구현·튜닝·벤치마크 비용. 문제별 탐색 예산과 분리하되, 평가용 계정·신캐·보스의 정답을 튜닝에 사용하지 않음 |
| 재사용할 사전 계산·학습 | 원래 수행한 시뮬 횟수, 데이터·평가기 버전, 적용 가능한 조건, 새 문제를 보기 전에 이용 가능했던 정보 |
| 캐릭터 추가에 따른 주기적 갱신 | 추가 데이터 생성·재학습·후보와 캐시 갱신·검증 등 해당 기법에 필요한 작업의 실제 시뮬 횟수, 계산 비용, 전체 경과 시간. 재사용한 자료와 갱신 범위도 기록 |
| 새 문제의 준비·탐색 | 입력이 주어진 뒤 그 문제를 위해 수행한 준비·적응·기준선 평가·큐브와 컨트롤 탐색·최종 검증의 실제 시뮬 횟수 |

1회는 **스쿼드 하나의 180초 평가**다. 새 요청으로 5덱 한 벌을 검증하면 5회이며, 배치 호출·병렬 실행으로 묶어도
횟수를 줄여 세지 않는다. 동일 조건의 캐시 적중과 이미 평가한 스쿼드의 재조립은 추가 시뮬 0회지만,
사용한 캐시의 양·생성 비용·출처는 남긴다. 새 타깃을 위한 사전 계산은 준비 비용으로 포함한다.
여러 계정에 공유하는 보스별 사전 계산이나 캐릭터 추가 후 갱신도 전체 비용과 문제별 비용 배분 기준을 밝힌다.
공유 비용은 한 번 발생한 총량과 계정별 배분량을 구분해 중복 합산하지 않는다.

재사용 자료가 없는 경우와 같은 출발 자료를 재사용하는 경우를 나눠 비교한다. 문제별 비용을 비교할 때는
준비와 탐색을 합산하고, 준비 비용을 제외한 온라인 탐색 횟수는 별도 항목으로 표시한다.
학습·후보 생성·5덱 조립 자체의 계산 시간은 시뮬 횟수와 섞지 않고 별도로 기록한다.

주기적 갱신에서는 필요한 캐릭터 데이터·평가기 구현이 준비된 시점부터, 갱신과 검증을 마쳐 계정별 탐색에
사용할 수 있는 시점까지의 전체 경과 시간을 잰다. 외부 평가기 구현 대기·작업은 별도로 밝혀 출시 후 지연과 구분한다.
사용 장비·병렬도와 작업별 시간·계산 비용을 함께 남긴다. 초기 학습 비용과 반복되는 갱신 비용도 구분한다.
갱신이 며칠씩 걸려 활용을 지연시키지 않아야 한다는 [운영 조건](GOALS.md#반복해서-새-문제를-푸는-능력)을 검토하되,
구체적인 시간 상한은 아직 미정이며 임의로 수치를 확정하지 않는다.

## 풀 수 있는 문제인가

- **일반적인 전체 공간에서 전역 최적을 보장하지 않는다.** 평가기는 블랙박스이고, 보유 100명이면 5인 조합만 약 7,500만
  개에 배치 순서·큐브·컨트롤이 곱해진다. 전수 탐색이 가능한 작은 공간에서는 최적해를 구해 검증에 쓴다.
- **예산 안에서 유력한 대안을 발견하는 능력을 잰다.** [벤치마크](#성능-측정)에서 최고 성능과
  유력 뼈대의 발견 범위를 함께 평가한다. 한 군집의 국소 최적에 도달한 것으로 다른 군집까지 탐색했다고 보지 않는다.
- **전투 계산의 정본은 외부 평가기다.** 버스트 순서·버충량·쿨감·시너지의 계산을 이 레포에 복제하지 않는다.
  이 레포는 무엇을 몇 번 평가할지 정한다. 스킬·구조 정보와 평가기 인터페이스로 받은 세부 전투 기록은
  후보 생성·학습·군집화에 활용할 수 있다. 총딜 하나만 관찰해야 한다는 제약은 없다.
  확정된 자원·조작 제약과 성능에 대한 경험칙을 구분하며, 경험칙이나 과거 사용 빈도만으로 가능성을 영구 제거하지 않는다.
- **학습용 딜 라벨은 계정·보스·운용 조건별 시뮬 결과다.** 실전의 정답을 뜻하지 않는다. 랭커 데이터는 딜 수치로 쓸 수 없으므로
  (아래 「지식의 세 출처」) 라벨이 아니라 "무엇부터 돌려 볼지"의 사전 지식이다.

## 핵심 구조: 스쿼드 탐색과 5덱 조립을 연결한다

덱끼리는 서로 영향을 주지 않는다(같은 보스를 각자 따로 친다). 따라서
**총점 = 스쿼드 점수의 합**이다. 다만 캐릭터 중복과 계정 자원 제약 때문에 독립적으로 좋은 스쿼드 5개를
고르는 것만으로는 편성안이 되지 않는다. 큐브 재사용·장착 한도 등은 실제 게임 규칙을 확인해 적용한다.

1. **어떤 스쿼드가 좋은가 — 어려운 부분.** 평가가 비싸고 시너지가 합산되지 않는 블랙박스다.
   조합·배치·큐브·컨트롤을 해당 단계의 탐색 변수로 삼고, 유력한 여러 뼈대의 기록을 유지한다.
2. **자원 제약을 지켜 5덱으로 조립한다.** 기본 형태는 가중 집합 패킹이다. 기존 실험은 평가한 후보 풀에서
   딜 합이 가장 높은 한 벌을 분기 한정으로 정확히 고른다. 이는 전체 탐색 공간의 전역 최적을 뜻하지 않는다.
   목표는 성능과 구조가 다른 여러 편성안을 반환하도록 확장하는 것이다.
3. **조립 결과를 다음 탐색에 되먹인다.** 한 덱의 점수만 올리는 수뿐 아니라 핵심 자원 이동·여러 덱 재구성으로
   전체 편성안과 후보군을 개선할 수 있는 수를 고른다. 여러 뼈대를 유지하는 기능은 아직 미구현이다.

## 지식의 세 출처

| 출처 | 강점 | 약점 |
|---|---|---|
| **랭커 덱** (에닉 → `nikke-analysis`) | 수많은 시행착오가 걸러진 결과. 사용률(티어)·자주 붙는 짝·버스트 구성 틀이 드러나 있고, 보스가 바뀌어도 대략적 추세는 비슷하다 | **딜 수치는 쓰지 않는다** — 랭커의 육성 정보가 없고, 과거 보스는 시뮬레이터에 없어 시뮬딜과 맞춰 볼 수 없다. 신캐·새 보스에는 기록이 없다 |
| **시뮬레이터** (외부 계산기) | 명시한 육성·보스·운용에서의 시뮬딜 | 비싸고, 실전 정확도·미지원 기믹은 별도 확인이 필요 |
| **구조 특징·제약** (버스트 단계 B1/B2/B3, 역할, 자원 한도 등) | 불가능한 후보 제거와 후보 생성·군집 구분에 활용 | 특징만으로 실제 시너지나 좋은 조합을 확정할 수 없음 |

## 접근 (초안)

아래는 네 단계 목표를 위한 설계 방향이다. 현재 실험 코드가 모두 구현한 흐름은 아니다.

```text
 계정·보스 패턴·운용 범위 확인 ── 평가기 지원, 자원 제약, 고정 조건과 탐색 변수 구분
     │
     ▼
 후보 생성 ── 랭커 이식 · 서로 다른 뼈대에서 출발 · 틀 재구성 · 단계에 맞는 큐브·컨트롤
     │
     ▼
 다음 평가 선택 ── 성능 개선 가능성 · 미탐색 뼈대 · 운용과의 상호작용 (필요시 대리 모델)
     │
     ▼
 180초 시뮬레이션 ── 요청·결과·조건 기록, 같은 평가 조건의 캐시 재사용
     │
     ▼
 후보군 유지·조립 ── 유력 뼈대별 후보 보존, 중복·자원 제약을 지킨 여러 5덱 편성안
     │
     ▼
 개선과 새 구조 탐색 ── 국소 개선 · 핵심 자원 재분배 · 여러 덱 재구성 · 운용 대안
     │
     └──── 예산이 남았으면 위로 반복

 출력: 군집별 대표안 · 시뮬 성능 · 구조 차이 · 재현 가능한 설정 · 실전 확인 사항
```

- **다양성은 탐색 중에도 유지한다.** 다중 출발·큰 틀 재구성·군집별 유력안 보존을 기존 국소 탐색과 비교한다.
  방법은 [`AI_분석가이드.md`](../AI_분석가이드.md)에 따라 기준선과 소수 후보부터 검증해 고른다.
  군집화만으로 좋은 조합이 생성되지는 않으며, 특정 모델이나 군집 수를 먼저 확정하지 않는다.
- **큐브·컨트롤은 조합과 함께 탐색한다.** 고정 운용에서 낮게 나온 조합을 영구 탈락시키고 상위만 운용 최적화하면
  놓치는 후보가 생길 수 있다. 모든 곱집합을 전수 평가할 필요는 없지만 다른 운용과 결합한 가능성을 평가할 기회를 둔다.
- **대리 모델은 다음 평가를 고르는 보조 수단이다.** 기존 「니케 + 짝」 회귀를 기준선으로 삼을 수 있다.
  계정을 넘는 모델은 육성, 운용을 넘는 모델은 큐브·컨트롤, 보스를 넘는 모델은 패턴 정보를 다뤄야 한다.
  모델의 예측 오차와 불확실성은 별도 검증하고, 최종 추천은 실제로 평가한 결과에 근거한다.
- **시즌 단위 사전 계산.** 보스가 공개되면 표준 육성으로 유력 스쿼드를 미리 돌려 캐시를 만드는 방식을 검토한다.
  다른 계정·보스·운용에서는 후보 생성의 사전 지식으로 쓰되, 조건이 다른 결과를 캐시 적중으로 취급하지 않는다.
- **캐릭터 추가 후 지속 적용.** 선택한 기법에 필요한 자료·모델·후보 등을 갱신하고, 확장된 캐릭터 풀에서
  같은 절차로 계정별 편성을 탐색한다. 추가된 니케를 넣는 수뿐 아니라 기존 니케의 덱 간 재배분도 다룬다.
  스킬 특성·유사 니케의 지식 활용은 비교할 후보이며 필수 절차가 아니다. 갱신 방법은 해 품질·시뮬 효율·갱신 비용으로 검증한다.
- **새 보스 적응.** 과거 보스의 지식은 출발점으로 쓰고 새 패턴에서 다시 탐색·검증한다.
  여러 보스를 함께 학습하는 조건부 모델은 검토할 방법 중 하나다. 임의 패턴 대응을 특정 모델 도입과 동일시하지 않는다.
  정적 조건뿐 아니라 시간 패턴·컨트롤 상호작용을 분리해 시험한다.

## 성능 측정

다음은 새 목표를 위한 검증 계획이다. 시뮬 성능·구조적 다양성·실전 유효성을 구분하고, 실전 자료가 없는 항목은 미검증으로 남긴다.

| 관점 | 평가할 것 |
|---|---|
| 성능 | 같은 계정·보스·자원·평가 예산에서 랭커 이식, 기존 국소 탐색 등 기준선 대비 최고 5덱 합과 각 대표안의 성능 차이 |
| 유력 뼈대 발견 | 사전에 정한 성능 기준을 만족하는 서로 다른 뼈대의 발견 수·중복 정도. 작은 탐색 공간의 참조 후보군 대비 누락도 확인 |
| 군집의 의미·안정성 | 구조 차이를 설명할 수 있는지, 군집 기준이나 탐색 시드를 바꿔도 주요 대안이 유지되는지. 멤버 교체 수나 군집 수만으로 성공 판정하지 않음 |
| 공동 탐색의 효과 | 조합을 먼저 확정하고 운용을 붙이는 기준선과 조합·큐브·컨트롤 공동 탐색을 같은 총예산으로 비교. 컨트롤에 따라 순위가 역전되는 후보를 발견하는지 |
| 새 문제의 시뮬 효율 | 같은 총 시뮬 예산에서의 최고 5덱 합과, 사전에 정한 해 품질에 처음 도달한 시뮬 횟수. 준비 비용 포함 |
| 계정·신캐·보스 대응 | 개발에 쓰지 않은 보유·육성·자원·조작 제약, 캐릭터 추가, 보스 패턴에서의 성능·군집 발견. 정적 속성 변경과 시간 패턴 변경을 구분 |
| 주기적 갱신의 실용성 | 캐릭터 추가 후 갱신 전체의 실제 시간·계산 비용과 갱신 후 계정별 해 품질·시뮬 효율·유력 대안. 계정별 탐색 비용과 구분 |
| 실전 비교 가치 | 대표안의 운용을 재현할 수 있는지, 가능한 조작 변화에서 결과가 얼마나 변하는지. 실제 딜과의 차이·순위는 실전 자료로 별도 확인 |

- **참조값의 범위를 명시한다.** 작은 로스터·제한된 운용 공간에서 전수 탐색했다면 그 공간의 최적해·유력 군집과 비교한다.
  큰 예산 탐색으로 얻은 값은 알려진 최고값이며 전역 최적의 증명이 아니다.
- **예산별로 함께 보고한다.** N = 10 · 100 · 1,000 · 10,000 등의 시점에서 최고 성능, 대표안 성능, 발견한 유력 뼈대를 기록한다.
  초기 기준선 평가·운용 대안 평가도 비용에 포함하고, 사전 계산·캐시 사용량은 구분한다.
- **새 계정·신캐·보스 검증에서는 적용 상황에 맞게 자료를 나눈다.** 미관측 계정·캐릭터·패턴으로의 일반화와 새 타깃에서 시뮬을 추가한 후의 적응을
  구분한다. 적응용 시뮬은 허용된 예산으로 세고, 미래 랭커 결과나 평가용 참조해는 후보 생성·튜닝에 섞지 않는다.
  같은 뼈대의 유사 조합이 양쪽에 섞여 새 뼈대 예측력을 부풀리는지도 확인한다.
- **성공 기준은 실험 전에 정한다.** 허용 성능 차이·대표안 수의 상한·구조 구분법과 실용적 개선 기준을 기록한다.
  구체적 수치와 방법은 아직 미정이며, 분석 가이드에 따라 검증 결과와 미확인 사항을 구분한다.

### 해 품질과 필요한 시뮬 횟수

- **예산별 최고해**: `S_best(N)`은 준비·탐색을 합쳐 N회까지 사용했을 때, 모든 구성 덱이 해당 조건에서 검증된
  유효한 5덱 편성 중 최고 합산 딜이다. 아직 유효한 한 벌을 못 만들었으면 미확보로 표시한다.
  동일 입력의 한 탐색 실행에서는 기존 최고해를 보존하며, 후보군 다양성은 별도 지표로 함께 본다.
- **목표 품질 도달 비용**: 같은 조건의 참조 점수 `R > 0`과 허용 차이 `ε`를 미리 정하고,
  `S_best(N) ≥ (1−ε)R`을 처음 만족한 시뮬 횟수를 기록한다. 예산 내 미도달은 그대로 보고한다.
  참조가 큰 예산 탐색의 알려진 최고값이면, 이는 참조 대비 도달 기준이며 전역 최적 오차의 보장이 아니다.
- 각 문제와 예산에서 기준선 대비 차이, 도달 횟수, 미도달 비율을 비교한다. 여러 문제의 중앙값·분포와
  어려운 사례를 함께 보고, 확률적 탐색은 시드별 변동도 본다. 한 계정·한 보스의 최고 결과만으로 효율을 주장하지 않는다.
- N의 예시나 `ε`는 제품의 고정 제한이 아니다. 벤치마크별 비교 예산·허용 차이·개선 기준을 실험 전에 정한다.

### 두 차수의 검증 순서

| 차수 | 남겨 둘 평가 상황 | 확인할 것 |
|---|---|---|
| **1차 — 허수아비, 1~3단계** | 명시한 정적 타깃에서 미관측 계정·육성·큐브·조작 제약, 신캐 추가 | 조합·배치·큐브·컨트롤 공동 탐색의 해 품질·시뮬 횟수·유력 대안. 고정 운용 및 조합 확정 후 운용을 붙이는 기준선과 비교 |
| **2차 — 임의 보스, 4단계** | 개발에 쓰지 않은 보스의 시간 패턴과 계정·신캐 변화의 조합 | 과거 지식으로 시작해 새 패턴에서 적응하는 비용과 품질. 속성·방어력 변경 실험과 시간 패턴 실험을 분리 |

캐릭터 추가 시험에서는 다음 순서로 갱신 후 지속 적용을 검증한다. 기존 캐릭터를 가려서 시험했다면
실제 신캐 출시를 모사한 시험임을 밝힌다.

1. 추가 전에는 해당 캐릭터의 랭커 기록과 시뮬 결과를 사전 자료에서 제외하고 기법을 준비한다.
2. 캐릭터 데이터·평가기 구현을 사용할 수 있게 한 뒤 미리 정한 절차로 필요한 시뮬 데이터 생성·학습·검증 등 갱신을 수행한다.
   갱신 전에 신캐 성능을 바로 예측하는 능력은 필수가 아니다. 갱신의 전체 비용·시간과 이용 자료를 기록한다.
3. 갱신 후 개발에 쓰지 않은 보유·육성 조건의 계정들에서 조합을 탐색한다. 신캐 보유·미보유 조건을 구분하고,
   새 니케 편입과 기존 니케의 덱 간 재배분을 포함한 5덱의 해 품질·시뮬 효율·유력 대안을 평가한다.
   계정별 준비·적응 시뮬을 허용하되 갱신 비용과 별도로 세며, 같은 확장된 풀·계정 조건에서 기준선과 비교한다.

새 보스 시험도 패턴 명세·평가기 지원을 입력으로 허용하되 해당 보스의 랭커 정답·평가용 참조해는 탐색에 제공하지 않는다.
최종 검증에서는 알고리즘·갱신 절차와 설정을 고정한다. 그 절차에 따른 재학습으로 모델 파라미터가 바뀌는 것은 허용한다.
갱신용 자료와 독립적인 평가용 참조해를 구분한다. 결과를 보고 사람이 규칙을 다시 조정하면 개발 비용으로
기록하고 별도의 미관측 문제에서 다시 검증한다. 허수아비 기준 프리셋·평가 문제 묶음·수치 기준은 아직 미정이다.
