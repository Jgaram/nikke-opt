# 평가·실험 규칙

탐색·평가기·시뮬레이션·실험 결과를 다룰 때 적용한다. 제품 목표는 [GOALS.md](../docs/GOALS.md),
검증 설계는 [SEARCH.md](../docs/SEARCH.md#성능-측정), 분석 방법 선택·보고는 [AI 분석 가이드](../AI_분석가이드.md)를 따른다.

- **평가는 항상 180초 전체 시뮬레이션이다.** 짧은 구간(30초 등)의 딜로 선별·순위를 매기지 않는다.
- **예산은 실제 평가 횟수로 센다.** 벽시계 시간이 기준이 아니며 캐시 적중·동일 요청 중복은 추가 시뮬 횟수에 넣지 않는다.
  스쿼드 하나의 180초 평가가 1회이며 배치·병렬화로 횟수를 줄여 세지 않는다. 비교 실험에서는 개발·재사용 사전 계산과
  새 문제의 준비·탐색 비용을 구분하고, 새 문제를 위한 준비 시뮬도 비용에 포함한다. 세부 집계는 [탐색 설계](../docs/SEARCH.md)를 따른다.
- **효율은 같은 횟수에서의 해 품질과 같은 품질에 도달하는 횟수로 검증한다.** 시간 상한을 임의로 성공 기준에 넣지 않는다.
  미관측 계정·신캐·보스의 평가용 정답을 탐색·튜닝에 섞지 않고, 허수아비의 정적 조건과 보스 시간 패턴의 검증을 구분한다.
- **한 편성안 안에서 한 니케는 한 번만 사용한다.** 대안 편성안끼리는 공유할 수 있다.
  계정의 큐브 자원·장착 제약과 실행 가능한 조작 조건을 지킨다.
- 고정한 조건과 탐색하는 변수를 명시한다. 평가기 기본 운용이 적용된 실험을 「컨트롤 없음」으로 보고하지 않는다.
- 보스 패턴의 출처·가정·평가기 지원 범위를 확인한다. 미지원 기믹을 생략한 결과를 해당 패턴에서 검증된 결과로 제시하지 않는다.
- 결과에는 평가기·버전·육성·보스 패턴·배치·큐브·컨트롤과 군집 구분의 근거를 남긴다.
  조건이 다른 과거 결과를 캐시 적중으로 취급하지 않는다.
- 시뮬 성능, 대리 모델의 예측 오차, 컨트롤 민감도, 실전과의 오차를 구분한다. 실전 자료가 없으면 실전 우위는 미검증이다.
- 기존 실험의 범위를 넘어 일반화하지 않는다. 미실행·실패·미지원 사항은 결과와 함께 명시한다.
